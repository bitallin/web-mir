## 1. 审计结论摘要

### 1.1 MVP 是否真正达到完成标准

**是：DoD 的功能、容量、恢复与备份项全部通过；但这是“有条件通过”，条件
是在 Alpha 0.1 关闭 8 项 P1（含 CI E2E 与测试隔离），功能本身没有缺失。**

- 产品主链路真实可跑：注册→登录→创建角色→主城→野外→移动→战斗→经验/
  金币→掉落→拾取→装备→重登恢复→聊天→PvP→复活→后台查询/Kick/内容发布/
  回滚，均由真实 PostgreSQL + 真实 WebSocket + 真实浏览器验证。
- 服务端权威、事务、幂等、租约、AOI、崩溃恢复、指标与部署均有实现和测试，
  不是空壳或 Mock。
- 但验收基础仍有一处不完整：**CI 的 E2E job 无法启动**（缺 PostgreSQL 与
  连接串），浏览器门禁在 CI 中从未执行（TD-OPS-01）。
- 50 人 10 分钟容量目标已由本轮补齐：50/50 加入，tick p95 8.79ms、
  p99 12.47ms，0 资产失败（§3.1）。
- 另有 8 项 P1 品质/安全问题，主要集中在战斗手感、测试隔离、封禁重连、
  内容发布安全和 Room 体积。

### 1.2 是否适合进入 Alpha

**适合，但先做 2 周的 Alpha 0.1“可信度与体验止血”。** 不建议直接开始
Alpha 0.2 的玩法扩张；否则会把不可靠的验收基线和手感问题带进下一阶段。

### 1.3 最重要的三个判断

1. **工程质量高于一般 MVP**：数据一致性、幂等、审计、内容版本、恢复演练
   都有真实证据；没有发现资产复制/丢失的正常路径。
2. **游戏质量仍是原型**：内容 30–60 分钟见底、一次点击一次攻击、三职业外观
   相同、金币无用途、怪物威胁偏低且死亡无代价。详见 `docs/GAMEPLAY_REVIEW.md`。
3. **测试“本地可信、CI 不可信”**：本地 329 个测试与 20 个 E2E 全过；CI 的
   E2E job 起不来；E2E 与开发栈共享数据库会在并发时产生假失败（本轮复现）。

### 3.1 容量结果

（本节由本轮实测填写，见 `docs/phase-reports/audit-2026-11-25/load-*.json`）

- 30 名玩家（其中 10 名持续攻击），600 秒：30/30 加入，接受 36,000 条、拒绝

  p95 32.28ms，出站 195.6MB、入站 5.9MB、patch 91.9MB，337 击杀，0 资产失败，
  重连率 0%。
- 50 名玩家（其中 10 名持续攻击），600 秒：50/50 加入，接受 60,000 条、拒绝
  11,088 条，tick p50 1.57ms / p95 8.79ms / p99 12.47ms / max 14.54ms，资产
  事务 p95 38.79ms，出站 445.2MB、入站 8.9MB、patch 251.4MB，317 击杀，0 资产
  失败，重连率 0%。满足“50 人持续 10 分钟”的容量目标。
- 拒绝码主要是 OUT_OF_RANGE（攻击者未先靠近目标）与 COOLDOWN，不是限频或
  服务端过载；与阶段 8 历史结论一致。
- 口径说明：`LOAD_ATTACKERS` 是 `LOAD_PLAYERS` 的子集，30/50 是在线总人数；
  阶段 8 报告的“30+10”也是 30 人（10 人攻击），不是 40 人。若目标需要
  40 人（30 移动 + 10 攻击），应设 `LOAD_PLAYERS=40 LOAD_ATTACKERS=10`。
- 对照阶段 8：30 人 10 分钟 tick p95 3.6ms / p99 6.13ms，资产 p95 33.2ms，
  0 资产失败；50 人 150 秒 tick p95 6.05ms。本轮复测数值同量级。

### 3.2 恢复演练结果

`pnpm drill:recovery` 通过（证据 `recovery-drill.json`）：

- SIGTERM：角色从 (17500,10500) 移动到 (18500,10500)，优雅关闭后重连位置与
  持久化位置一致；物品实例 2→2；租约 1ms 释放。
- SIGKILL：等待 45 秒让 20 秒周期 checkpoint 落盘后强杀；重连位置与持久化
  位置一致；物品实例 2→2；租约 23,089ms 后过期，角色可重新入图。
- 结论：正常重启与崩溃恢复都不会丢失已提交资产；未 checkpoint 的瞬时状态按
  设计回退到最近快照。

## 4. 十五个维度的审计结论

### 4.1 整体架构与模块边界

**结论：良好。** pnpm monorepo、11 个包、4 个 app；`contracts` 单一协议；
ESLint `no-restricted-imports` 强制依赖方向；审计未发现违规导入。领域逻辑
（战斗/掉落/移动/内容）与 Room、数据库、HTTP 分离真实存在，不是目录占位。

问题：

- `WorldMapRoom` 2,178 行，承担 10 类职责（P1，TD-SRV-01）。
- `GameScreen` 900 行、`useWorldSession` 840 行，客户端表现层偏大（P2/P3）。
- `packages/game-application` 只有 `AssetService`，未来交易/商店/任务会继续
  堆进同一文件，需要按用例拆分。

### 4.2 前端架构与 Phaser 生命周期

**结论：基本正确，存在体验与性能债务。**

- Scene 在 `SHUTDOWN` 时移除 input/scale 监听；E2E 验证 restart 不重复监听。
- 传送时销毁并重建整个 `Phaser.Game`（TD-CLI-04），聊天/战斗历史清空。
- 无本地移动预测，ack 后才移动（TD-CLI-07 关联）。
- 20Hz state patch 触发 React 全量重渲染 + 小地图重绘（TD-CLI-05），软件渲染
  25 FPS。

### 4.3 游戏表现与 React UI 分层

**结论：分层清晰，HUD 质量需重做。**

- Phaser 负责世界、角色、怪物、掉落、浮字、音效；React 负责 HUD/面板/表单。
- 战斗面板占据屏幕中下部，常驻拒绝提示压住技能栏（TD-CLI-02）。
- 物品无图标、无品质、无装备对比；文字对比度偏低。
- 三轮截图见证据目录 `03-town-hud.png`、`05-combat.png`、`07-inventory.png`。

### 4.4 Colyseus Room 与实时网络

**结论：协议与命令管线扎实，广播策略需优化。**

- 每条客户端消息有 Zod schema、协议版本、序号、限频、幂等、错误码。
- 移动/战斗/资产三套命令都验证会话与地图；重复 commandId 重放原结果。
- 战斗事件全 Room 广播，不按 AOI（P1，TD-SRV-02）。
- 资产事务单队列（P2，TD-SRV-03）。
- 管理命令幂等只在内存（P2，TD-SRV-06）；Outbox 不分区服（P2，TD-SRV-07）。

### 4.5 服务端权威模拟

**结论：达标。** 客户端只提交目标 tile、目标 id、技能 id、物品 id；位置由
服务端 BFS + 固定 tick 推进；伤害/命中/暴击/掉落/金币/经验全部服务端计算。
无客户端可提交最终坐标、伤害或奖励的路径。E2E 的战斗/PvP/安全区用例验证了
拒绝路径。

### 4.6 移动、碰撞、寻路与 AOI

**结论：核心正确，手感与实体碰撞不足。**

- 服务端 BFS、轴对齐路径、整数子格推进、非法路径拒绝、传送门自动触发。
- AOI 8×8 cell、radius 1，StateView 增量 add/remove/delete；集成测试锁定
  远处不可见、近处可见、离开释放。
- 无键盘移动、无停止、无本地预测（TD-CLI-07）；实体无碰撞（TD-SRV-09）。

### 4.7 战斗系统与怪物 AI

**结论：权威且可复现，内容深度不足。**

- 固定 3 次 RNG 抽取（命中/暴击/浮动），种子回放确定；怪物 FSM 完整。
- 只有 2 种怪物、每职业 1 个技能、无 MP 回复；怪物伤害低、死亡无惩罚。
- 战斗事件全图广播导致他人治疗被记成自己的（TD-CLI-03）。
- 详细数值与体验见 `docs/GAMEPLAY_REVIEW.md` §3.2–3.4。

### 4.8 背包、装备、掉落与经济

**结论：事务正确，经济闭环未成立。**

- 物品实例唯一位置 CHECK、并发拾取唯一成功、钱包+账本同事务、装备槽行锁。
- 金币无消耗端、材料无用途、武器不掉落、只有一件可掉落护甲。
- 过期未领取掉落永不删除：开发库 781 条掉落全部过期，706 件物品实例滞留
  ground，审计结束时增至 763 件（P2，TD-DATA-02）。
- 击杀奖励按基础属性裁剪 HP/MP，忽略装备（P2，TD-DATA-01）。

### 4.9 数据库事务、幂等与一致性

**结论：本项目的强项，无 P0/P1 数据缺陷。**

- 票据单次消费、租约、资产命令幂等、账本唯一键、并发拾取、装备交换、背包满、
  药水幂等、重登快照均有真实 PostgreSQL 集成测试。
- 开发库不变量：钱包与账本差异 0、负余额 0、重复装备/背包槽 0、地面物品无
  掉落行 0、已领取仍在 ground 0。
- 仍需处理：checkpoint 跨地图覆盖（TD-DATA-03）、装备槽唯一性只在应用层
  （TD-DATA-05）、幂等键不含角色（TD-DATA-06）。

### 4.10 断线重连与 Game Server 崩溃恢复

**结论：设计完整，存在一个封禁绕过缺口。**

- 15 秒重连宽限、断线玩家不可被怪物选中、租约 30 秒、20 秒 checkpoint、
  正常离开立即保存、SIGTERM 先 drain 再释放租约。
- 封禁/踢下线使用 `leave(4000)` 进入宽限期，修改过的客户端可在 15 秒内用旧
  token 恢复会话（P1，TD-SRV-04）。
- 传送后若客户端不再连接，旧 Room 会残留会话记录（P2，TD-SRV-05）。
- 本轮已重跑 SIGTERM/SIGKILL 演练并通过（§3.2）。

### 4.11 内容数据驱动与版本管理

**结论：版本化与不可变 Release 达标，发布安全有缺口。**

- `content-schema` 基线、引用/范围校验、稳定 checksum、不可变 Release、
  按区服激活、旧 Room 固定快照、回滚为新激活记录，均有测试与 E2E。
- 发布前不校验“是否删除仍被玩家持有的物品模板”，可造成登录事故（P1，
  TD-DATA-04）。
- 后台发布/校验使用已保存草稿而非编辑器内容（P2，TD-OPS-03）；草稿全局
  last-write-wins（TD-OPS-04）；Release 列表 100 条上限（TD-OPS-05）。

### 4.12 运营后台与管理权限

**结论：RBAC/审计/Outbox 真实可用，多区服与交互细节待完善。**

- 管理员身份与玩家身份分离、8 小时 HttpOnly Cookie、服务端 RBAC、每个写操作
  原因必填、成功与失败审计、审计+Outbox 同事务、append-only 触发器。
- Kick/Ban/Mute 经 Outbox 到 Game Server，按 commandId 幂等（进程内）。
- 无登录审计/会话撤销/MFA；内容操作隐式绑定第一个活跃区服；释放列表无分页。
- E2E（独立库）验证登录、总览、Room、玩家详情、Kick、审计、内容发布/回滚。

### 4.13 日志、指标与异常监控

**结论：指标覆盖充分，告警与追踪有缺口。**

- Pino 脱敏；Game Server `/metrics` 与 `/metrics/prometheus` 覆盖 Room/玩家/
  tick/命令/聊天/战斗/资产/掉落/WS 上下行/连接/断线/重连；Control API 覆盖
  HTTP/Outbox/DB/运行时。
- 30 人（10 名攻击）压测 tick p95 3.58ms，资产 p95 32.28ms；50 人（10 名
  攻击）tick p95 8.79ms。
- Outbox 失败告警对 gauge 使用 `increase`，可能不触发（TD-OPS-13）；无分布式
  追踪/请求链路；WS 指标按 Room 聚合，无单会话标签。

### 4.14 Docker、部署与 CI/CD

**结论：部署拓扑真实，CI 与部分脚本不达标。**

- 4 个镜像、非 root Node 服务、nginx edge（HTTPS/WSS/安全头/限流/内部端点
  404）、Prometheus 4 目标、部署/回滚/备份/恢复演练脚本、runbook 齐全。
- **CI 的 E2E job 无数据库，永远无法通过**（P1，TD-OPS-01）。
- 两个静态 nginx 镜像以 root 运行，与阶段 8 报告“全部 non-root”不符
  （TD-OPS-10）。
- 备份 manifest 与 dump 非同一快照、恢复不校验 SHA-256（TD-OPS-08）。
- 回滚 runbook 缺少 compose 必需变量（TD-OPS-09）；部署脚本不自动迁移/备份
  （TD-OPS-12）。

### 4.15 单元、集成、E2E 与压力测试

**结论：覆盖面真实，CI 与部分场景缺失。**

- 329 个测试覆盖领域、事务、并发、协议、Room join/leave/reconnect、内容
  校验、管理 RBAC/Outbox；20 个 E2E 覆盖双浏览器、传送、战斗、经济、PvP、
  聊天、断线重连、后台。
- E2E 共享开发库，与开发栈并发时假失败（P1，TD-OPS-02）。
- 50×10min 本轮已通过，但容量场景仍是人工运行、未纳入 CI（P2，TD-QA-01）；

## 7. 未验证或受限项

1. CI 上的 E2E 从未运行成功（本轮确认 job 配置缺失）。
2. 生产 compose 的浏览器截图无法在当前环境采集（浏览器不能访问宿主发布
   端口）；生产演练以脚本检查为准。
3. 真实公网延迟/丢包下的手感未测；局域网 RTT 45–172ms。
4. 桌面端 45 FPS 目标未验证：当前环境为软件渲染，实测 25 FPS；需在真实
   显卡/笔记本上复测。
5. 移动端/触屏未验证（MVP 不要求）。
6. 正式美术/音效不存在，当前全部为占位。
7. 多区服/多 Game Server/动态实例未实现，也未验证。
8. 长时间（>2 小时）内存泄漏未做 soak 测试；本轮 10 分钟压测观察首尾内存。
9. 内容 Release 删除物品导致登录失败的场景只做代码审计，未在测试中复现
   （建议 Alpha 0.1 补集成测试）。

## 8. 架构质量评价

**优点**

- 服务端权威与资产事务边界清楚，tick 内无 IO；这是长期扩展最重要的地基。
- contracts/schema/迁移先行，客户端与服务端共享 DTO，协议演进可控。
- 内容版本固定、不可变 Release、审计+Outbox、租约与幂等均为真实实现。
- 依赖边界由 lint 强制；没有“为看起来完整”的空壳包。

**不足**

- Room 与资产服务是“能工作的大类”，不是可组合的用例层；玩法一多会变成
  修改热点。
- 客户端表现层状态扇出过大，HUD 与战斗区竞争屏幕与主线程。
- 测试与交付的“最后一公里”不严：CI E2E、E2E 隔离、容量回归门禁、备份
  校验。
- 多区服/多实例的扩展点（Outbox 目标、内容按区服、实例路由）尚未设计，
  当前单区服假设渗透在后台与命令投递中。

**评价**：作为 MVP，架构质量高于平均；作为 Alpha 的起点，需要一次
“结构性整理”（Room 拆分、命令管线复用、测试隔离），但不需要推翻重来。

## 9. 游戏产品质量评价（摘要）

完整版见 `docs/GAMEPLAY_REVIEW.md`。

- 操作：点击寻路可用，但无键盘、无预测、无停止；一次点击一次攻击。
- 战斗：权威结算正确，但怪物威胁偏低、死亡无代价、无动画、无自动攻击。
- 职业：数值有差异，外观相同、技能各 1 个、道士定位模糊、无回蓝。
- 内容：2 图 2 怪 9 物品 3 技能 0 任务；30–60 分钟见底。
- 经济：金币/材料无用途，装备只有 1 件可掉落，无商店/交易。
- 多人：能看见、能聊天、能决斗；无组队/好友/公会/交易。
- 美术：统一但为占位（8 tile、1 角色贴图、几何怪物），不具备发布质量。
- HUD：信息齐全但拥挤、低对比、常驻警告、无物品图标。

**一句话**：系统闭环是真的，游戏体验还是原型；Alpha 0.2 应优先“手感、
职业差异、内容量与金币消耗”，而不是继续加系统。

## 10. Alpha 准入结论

**建议：有条件进入 Alpha，先执行 Alpha 0.1（2 周）。**

Alpha 0.1 门禁：

1. CI E2E 真实执行且 20/20；E2E 使用独立数据库。
2. 50 人 10 分钟压测通过并纳入回归门禁（本轮已通过，待自动化）。
3. 自动攻击与提示 toast 上线，手动杀怪只需 1 次锁定点击。
4. 封禁后旧 token 重连失败；删除被持有物品的 Release 无法发布。
5. 击杀奖励按装备属性持久化。
6. `WorldMapRoom` 完成第一阶段拆分（命令守卫/会话/视图同步）。
7. 无 P0/P1 未关闭。

满足后进入 Alpha 0.2（6 周）：三职业差异、4–6 种怪物、1–15 级内容、
15–20 件装备、商店金币回收、HUD/美术第一版。详细范围、里程碑、验收与风险
见 `docs/POST_MVP_ROADMAP.md`。
