# Alpha 0.2 S2 任务 1：服务端权威法力回复

- 日期：2026-11-25
- 版本：Alpha 0.2，切片 2 的第一项
- 关联：`docs/ALPHA_02_EXECUTION_PLAN.md`、`docs/GAMEPLAY_REVIEW.md`
  （“法师 80 MP 只够 8 次火球”）、ADR-027
- 证据：`docs/phase-reports/alpha-02/mana/`

## 1. 为什么先做这个

商店解决“金币没有用途”后，职业体验的下一个断点是资源不可持续：三职业各只有
一个技能，MP 只减不回，法师/道士在几次施法后只能普攻。先让法力按职业回复，
可以在不引入复杂技能系统的前提下，让“法师持续输出、道士持续辅助、战士偶尔
爆发”的定位开始成立；它也是 S2 后续 DoT/位移技能的公共基础。

## 2. 验收标准

1. 法力按职业每秒回复：战士 1、法师 3、道士 2；死亡期间不回复，复活回满。
2. 回复由服务端固定 tick 推进，客户端不能提交时间戳或回复量；相同步长产生
   相同结果（确定性回放）。
3. 回复速率来自内容 Release；旧 Release 缺少字段时视为 0，不改变其 checksum。
4. 达到上限后停止；药水/升级等外部修改后不会出现“积攒后爆发”。
5. 单元/内容/契约测试通过；浏览器 E2E 能看到 MP 下降后自动回满。
6. 不增加 tick 内 IO，不改变资产事务与现有战斗结算。

## 3. 实现

- `ClassContent` 增加可选 `mpRegenPerSecond`（0–100 整数）。基线：战士 1、
  法师 3、道士 2。
- `combatStatsFor` 将其带入 `CombatStats`；`CombatWorld` 为每个玩家保存
  毫秒余量，在 `step()` 中按整数秒结算，封顶 `maxMp`；死亡、满蓝、速率为 0
  时清空余量；复活/药水写回时重置余量。
- 没有客户端逻辑改动：MP 已由 Room 每 tick 同步到状态视图，HUD 自动显示。
- 旧内容 Release 不注入默认值，checksum 不变（与 ADR-026 的价格字段一致）。

## 4. 测试与证据

- 领域：`combatWorld.test.ts` 覆盖法师 3/秒、封顶、死亡不回复、注入内容速率；
  `stats.test.ts` 覆盖职业速率来源；`replay.test.ts` 快照更新为 79 MP，证明
  确定性回放包含回复。
- 浏览器：`tests/e2e/mana.spec.ts` 创建法师 → 进入野外 → 火球消耗 10 MP →
  观察 MP 下降后自动回满；截图 `mana-regenerating.png`、`mana-full.png`。
- 现有战斗 E2E 的“法力 24/30”断言改为“下降且在合理区间”，避免回复导致的
  精确值抖动。
- 全量门禁结果见本轮 WORKLOG 与 `PROJECT_STATUS.md`。

## 5. 独立审查与商店修复

本轮的独立审查（对 `9e0ad74`）发现并修复了：

1. `shop_buy`/`shop_sell` 账本幂等键未包含操作类型，复用同一 `commandId`
   会触发唯一约束并回滚；已改为 kind 前缀，并补回归测试。
2. 客户端“买 5/全部”忽略 `maxStack`/`SHOP_MAX_QUANTITY`；已按内容和协议上限
   钳制按钮数量。
3. 商店目录在异常内容/手改地图下可能在加入定时器内抛错；已改为逐商人
   `safeParse` + 目录整体 `safeParse`，失败只禁用商店并记录日志。
4. `grantKillReward` 仍保留“先写幂等行、再锁角色”的旧顺序；已改为先锁角色。
5. 补齐测试：买卖同 `commandId`、跨职业购买、并发整栈出售、出售重复回放、
   并发击杀奖励、3 格边界、超过堆叠上限。

对本轮法力回复做第二次独立审查，又修复两处低风险问题：

6. 战斗集成测试仍断言施法后 MP 精确等于 24，回复会让该值只存在约 1 秒；改为
   断言“MP 已下降”。
7. `setPlayerVitals` 对所有消耗品都清空回复余量，HP 药水会丢弃已积累的不足
   1 秒；改为仅在 MP 实际变化时清空，并补两条余量测试。

## 6. 未验证与风险

- 50 人容量回归尚未在新代码上复跑；法力回复只增加极小的 tick 开销，但仍需
  实测。
- 开发栈 84–87 仍运行 Alpha 0.1 代码；需重启并发布包含 `mpRegenPerSecond`
  的内容 Release 后，8584 才能看到回复。
- 数值（1/3/2）是初始平衡，未经长时间试玩；后续技能加入后需重新评估。
- 商店仍无买回/二次确认与数量输入，已记为产品债务。
