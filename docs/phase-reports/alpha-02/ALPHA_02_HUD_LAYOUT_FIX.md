# Alpha 0.2 体验修复：战斗 HUD 不再遮挡游戏画面

- 日期：2026-11-26
- 触发：用户试玩截图——中央「当前目标 / 技能 / 战斗记录」面板宽 500px 且随
  附近怪物数量增高，直接盖住角色与战斗视野
- 关联：`docs/PROJECT_ROADMAP.md` S4「HUD 重排」、TD-CLI-05、
  `docs/PROJECT_STATUS.md`

## 1. 问题

- `.combat-panel` 以 500px 宽居中贴底，内部依次放目标、掉落、技能与战斗记录；
  附近怪物一多，面板高度可达半屏，玩家角色和怪物都被压在面板后面。
- 技能、目标列表与战斗记录混在同一块面板里，任何一个区域变长都会挤压整个
  战斗区；面板没有收起方式。

## 2. 改动

### 2.1 布局

- 右侧新增 `hud-right` 纵向栏：上方是「小地图 + 附近玩家」，下方是「战斗信息」
  （目标、附近掉落、战斗记录）。战斗信息面板可收起为一行标题，状态在本次
  进入世界期间保留。
- 技能从战斗信息中拆出，成为底部居中的 `skill-dock`，高度固定，始终可达。
- 玩家面板裁剪溢出内容，「附近玩家」列表内部滚动；修复回归中发现的点击拦截：
  列表溢出的「攻击」按钮原本会被下方面板盖住（详见 §4）。
- 响应式：≤1180px 收窄右栏与技能坞并把聊天上移；≤860px 维持既有“移动端不
  支持”的简化布局。

### 2.2 交互

- 「战斗信息」标题栏增加「收起 / 展开」按钮（`combat-info-toggle`），
  `aria-expanded` 同步；收起时只保留标题，画面上只留下小地图与技能坞。
- 所有既有 `data-testid`（`target-panel`、`monster-row`、`skill-N`、
  `combat-log`、`player-row` 等）保持不变，自动化仍可操作。

## 4. 回归中发现的问题

第一次全量 E2E 中 `pvp.spec.ts` 的城镇安全区用例失败：点击「附近玩家」里的
攻击按钮时，`combat-panel` 的标题栏拦截了指针事件。根因是玩家面板设置了
`max-height` 但没有裁剪，内容溢出到下方战斗信息面板的区域；Playwright 看到
按钮“可见”，实际被另一块面板覆盖。修复为面板 `overflow: hidden`、列表内部
滚动并固定小地图/标题不收缩。修复后该用例与全量 31/31 通过。
