## 1. 目标

S1–S3 让玩家能买卖、有技能、怕死亡，但“打怪 → 掉落 → 装备 → 再成长”缺少
装备内容：掉落几乎只有皮甲，玩家没有“下一件装备”的目标。本切片让 1–7 级有
分层装备可追，让稀有掉落可感知，让玩家一眼看出新装备比身上强多少。

## 2. 交付内容

### 2.1 契约

- `ItemContent.quality?: 'common' | 'rare'`，缺省为 `common`；不写默认值以保持
  历史 Release 的 checksum（EL-004）。
- `ItemView.quality` 可选；`AssetService.itemView` 从内容读取后下发，客户端
  不需要另取物品目录。

### 2.3 内容校验（`packages/content-schema/src/validation.ts`）

- 错误：非装备物品设置 `quality`。
- 警告：装备没有任何获取途径（既不在掉落表、没有出售价，也不在初始装备中）。
  使用警告而非错误，避免历史 Release 在 `ContentStore` 加载时被新规则拒绝。

### 2.4 客户端

- `apps/game-web/src/lib/inventoryView.ts`：品质缺省、属性对比增量与文案、
  背包整理顺序；全部为纯函数并有单测。
- 背包：稀有品金色描边与“稀有”标签（`data-quality`）；装备显示
  “装备后 +X 攻击 / 较当前 ±属性”；新增“整理”按钮（只改变显示顺序）。
- 面板互斥：打开背包会关闭商店，打开商店会关闭背包，避免居中商店面板盖住
  背包控制区导致按钮不可点。

## 4. 遇到的问题及解决

1. **内容校验收紧会打断历史 Release。** 最初把“装备必须可获得”写成 error，
   `EL-004` 的 legacy payload 回归测试立即失败；`ContentStore` 在 Room 启动时
   会校验已存 Release，旧版本也会被拒绝。改为 warning，并保留
   “quality 仅用于装备”这个对历史数据无影响的 error 规则。
2. **掉落表测试依赖固定 RNG 序列长度。** 新增条目后 `forest_wolf` 的抽取次数
   变化，固定序列耗尽；测试改为按条目数生成序列，不再硬编码长度。
3. **商店面板遮挡背包。** E2E 发现商店打开时背包按钮被居中面板拦截；改为
   打开一方即关闭另一方。商店仍会覆盖顶部 HUD 开关（TD-CLI-14）。
4. **E2E 复用同一只史莱姆导致假失败。** `skills.spec.ts` 两个用例共用
   `wilds_slime_10`，道士用例先打掉部分生命/拉走仇恨，战士用例等待 attack 超时
   （TD-QA-11 同类）。给每个用例分配独立刷点后 2/2 稳定通过。
5. **装备属性显示不完整（试玩反馈）。** 背包与装备槽只显示主属性：带生命的
   皮甲/锁子甲只写“防御 +X”，而对比行却出现“生命 +Y”，两处信息不一致。
   把“物品属性行”收敛为 `itemStatLine`（攻击/防御/生命/法力/回复全量输出），
   背包、装备槽与商店共用同一函数；补充 3 条单元断言与 E2E 对“防御 +5 ·
   生命 +15”的校验。
