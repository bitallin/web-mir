# Alpha 0.3 S3-D2：到达类任务目标报告

- 日期：2026-11-27
- 切片：Alpha 0.3 S3-D2「到达类任务目标：地点、半径与探索进度」
- ADR：`docs/ADR/ADR-042-arrival-quest-objectives.md`
- 证据：`docs/phase-reports/alpha-03/reach-quests/`

## 1. 目标

任务此前只有“击杀”和“收集”两种动词，地图只是战斗背景。本切片增加第三种
目标：角色必须走到指定地图的指定区域。到达由服务端权威位置裁定，完成后持久化，
并接入既有的一键导航、任务面板与交付流程。

## 2. 交付内容

### 2.1 契约

- 内容目标新增闭集分支：
  `{ kind: 'reach', mapId, tile: { x, y }, radiusTiles }`，半径上限
  `QUEST_REACH_RADIUS_MAX = 5`。
- 视图新增：
  `{ kind: 'reach', mapId, mapName, tile, radiusTiles }`；地图名由服务端从编译
  地图解析，客户端不自行拼接。
- 任务进度约定为 0/1；面板与追踪器显示“已到达/未到达”，不显示 `0/1` 计数。

### 2.2 内容

| 任务                       | 类型   | 发布者       | 目标                        | 奖励               |
| -------------------------- | ------ | ------------ | --------------------------- | ------------------ |
| `quest_town_east_gate`     | 一次性 | 晨曦主城守卫 | 晨曦主城 (35,15)，半径 2 格 | 15 经验 / 5 金币   |
| `quest_daily_ruins_patrol` | 每日   | 废墟斥候     | 残垣废墟 (43,20)，半径 2 格 | 180 经验 / 35 金币 |

两条任务的坐标均已验证在地图内、可行走，且从出生点存在寻路路径。一次性任务
作为教学入口，每日任务把玩家带到废墟东侧，给探索一个可重复的目标。

### 2.3 领域

- `reachObjectiveMet(objective, mapId, position)`：地图匹配且玩家格与目标格直线
  距离 ≤ 半径时为真；只接受服务端位置。
- `questViewFor` 为到达目标解析地图名；进度直接使用任务行中的 0/1，不从当前
  位置实时派生，因此离开区域不会回退。

### 2.4 应用事务

`AssetService.completeReachQuest`：

1. 事务内先 `FOR UPDATE` 锁角色行，与接取/交付保持同一锁顺序；
2. 按内容 `rules.dailyReset` 计算当前周期键；
3. `FOR UPDATE` 读取该周期的任务行；
4. 只有 `active` 行写 `progress = 1`、`status = completed`、`completedAt` 与
   `version + 1`；`completed/claimed` 行原样返回；
5. 重复观测与并发观测幂等。

到达不改变物品、金币或经验，因此不写资产命令、金币账本或物品事务。

### 2.5 服务端观测

- 每个地图 Room 每 4 tick（20Hz 下 5Hz 周期）扫描在线会话的进行中到达任务；
  只比较内存中的权威位置与目标区域，不读数据库。
- 命中后把完成写入既有资产队列；同一 `角色:任务` 在飞行中去重，失败退避 2 秒
  后重试；会话离开时清理退避记录。
- 提交成功后更新会话任务记录、发送 `quest.update` 与完成提示；若该任务正在
  自动导航，则以 `completed` 停止导航。
- 每日任务只完成当前周期的行；旧周期行保持历史记录。

### 2.6 一键导航

- 沿用 `quest.navigate` 的 `hunt` 目的表示“前往目标”，不为到达新增协议。
- 目标在别的 map 时按传送门最短路由走过去；同图时用
  `findApproachPath(runtime, target, from, radius)` 选择最短可达落脚点。
- 到达任务不进入自动攻击；进入半径后清空路径，等待完成事务。

### 2.7 客户端

- 任务面板与追踪器显示「到达 晨曦主城（35,15）」与“已到达/未到达”。
- 行动按钮在到达目标上显示「前往探索」；导航横幅显示「自动探索」。
- 底部提示改为“前往击杀或前往探索自动寻路（击杀目标会自动战斗）”。
- 服务端完成提示与客户端状态通知沿用既有机制。

### 2.8 内容校验

- 目标地图必须存在于编译地图；
- 目标格必须在地图范围内且可行走；
- 半径必须在 1–5；
- 旧 Release 不含到达目标，schema 的加法扩展不改变其解析与 checksum。

## 4. 设计说明

1. **为什么不让客户端上报到达**：位置必须服务端权威；客户端只提交移动意图。
   若接受“我已到达”，改包客户端可以完成任意地点任务。
2. **为什么不在移动 ack 时判定**：服务端自动寻路、登录时已在区域、被击退等
   路径不会产生一个“手动移动完成”事件；tick 内的权威位置是唯一完整来源。
3. **为什么落状态而不是实时派生**：到达是“曾经发生过的里程碑”。像收集任务
   那样读当前位置会在玩家离开后回退；一次状态写入 + 条件更新才能幂等且持久。
4. **为什么复用资产队列**：完成写入虽不是资产命令，但仍要避开 20Hz tick 内的
   SQL 等待；复用既有串行队列也让任务行更新与奖励/接取保持顺序。
5. **为什么复用 `hunt` 目的**：新增协议目的会多一套幂等与校验面；到达与狩猎
   共享“前往目标”的语义，差别只在目标选择与是否战斗。

## 5. 问题与修正

- 未发现产品代码缺陷。验证过程中有三处适配：
  1. 新增两条任务后，任务面板的分组数量从 3/11 变为 4/12，
     `questChain.spec.ts` 的断言同步更新。
  2. 8584 手工验证脚本最初在角色尚未走到守卫身边时点击“接取并前往”，面板
     正确显示为“前往接取”；先移动到守卫范围后流程通过。这验证了距离校验
     仍然生效，不是缺陷。
  3. 全量 E2E 的 `combat.spec.ts` 出现两类时序失败：技能冷却只有 5 秒，断言
     排在两次法力轮询之后可能让冷却在检查前自然结束；另外停止自动攻击后仍有
     在途普攻，可能在存活检查与施法之间击杀目标，使施法被服务端正确拒绝。
     修正为：先检查冷却、再轮询法力；施法前等待 1 秒让残留攻击落地，若目标
     已死则等重生后施法。断言全部保留，没有降低或跳过用例。
  4. `movement.spec.ts` 的自动攻击接近用例被前序用例留下的“追击”状态影响：
     荒野实例里已有怪物在追其他玩家，角色不需要移动，采样自然看不到帧间
     预测。该 spec 改用 `?freshTransfer=1` 隔离自己的荒野实例（与任务引导
     E2E 相同），单跑 2/2、全量重跑通过，断言未改。
