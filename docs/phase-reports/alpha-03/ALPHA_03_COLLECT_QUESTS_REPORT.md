- 日期：2026-11-27
- 范围：任务目标从“只有击杀”扩展为“击杀 + 收集”，并把收集做成真实的
  物品消耗端。

- 证据：本目录 `collect-quests/`、`tests/e2e/collectQuests.spec.ts`、

## 1. 结论

收集任务已可用：任务面板与追踪器显示“收集 金创药 1/1”这类目标；接取后
背包够数即显示“可交付”；交付在一个事务里扣除物品、标记完成/已领取并发放
奖励；数量不足会整体回滚并提示“背包中的任务物品不足”。一键导航对收集任务
会走向掉落该物品的怪物，背包凑够后自动停止战斗，返回发布者交付。

本切片没有数据库迁移，历史 Release 不受影响；新增内容为两条任务：

| 任务           | 类型   | 发布者   | 目标      | 奖励             |
| -------------- | ------ | -------- | --------- | ---------------- |
| 巡路补给       | 一次性 | 守卫     | 金创药 ×1 | 20 经验 / 15 金  |
| 每日：收集蛛腿 | 每日   | 废墟斥候 | 蛛腿 ×3   | 220 经验 / 40 金 |

## 2. 设计要点

1. **背包即进度**：视图从服务端会话的背包快照汇总
   `templateId → 数量`；任务记录为 `active` 时，进度与“可交付”状态由当前
   持有量派生，拾取不写任务进度。避免“卖掉材料后进度仍显示完成”。
2. **唯一写入点是交付事务**：领取时先锁角色行，再 `FOR UPDATE` 锁住该模板
   的背包堆叠，按槽位扣除；数量不足返回 `QUEST_ITEMS_MISSING` 并回滚；
   足够时把行 `active → completed → claimed`，再发放经验/金币/物品。
3. **视图刷新不轮询数据库**：每次资产命令提交后，若该会话有进行中的收集
   任务，Room 用已更新的背包快照重发任务快照。
4. **导航复用既有意图**：收集任务的 `hunt` 目标集合来自战利品表（哪些怪物
   会掉该物品）；背包凑够后导航以 `completed` 停止；`return` 把“已够数”
   视为完成。
5. **内容校验防套利**：目标物品必须存在且为材料/消耗品；每日任务不能要求
   商店可购买的物品；目标物品不能同时是奖励；无掉落/商店来源时告警。

## 6. 未覆盖与风险

- 到达类目标（探索地点/半径）未实现，作为 S3-D2。
- 组队共享收集进度未实现；收集任务仍只由本人完成。
- 收集任务不显示物品来源（TD-CLI-21，P3）；描述需要写清去哪打。
- 预先持有物品即可交付是原型设计；每日任务的物品消耗是真实支出，重置仍按
  周期键隔离。
- 背包进度依赖 Room 的授权背包快照；当前单 Room 权威下一致，多进程/共享
  缓存阶段需要重新审视。
