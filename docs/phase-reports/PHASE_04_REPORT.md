> 日期：2026-11-24
> 状态：实现完成，自动化验收通过；待用户在 8584 端口实测确认
> 前置：阶段 0–3 已通过审阅与用户验收

---

## 1. 阶段概述

阶段 4 建立第一条服务端权威的 PvE 成长链路：

```text
编译地图 monsterSpawns
  -> Room 创建无 IO 的 CombatWorld（注入导航格、寻路、RNG、复活点）
  -> 怪物 FSM：idle -> patrol -> chase -> attack -> return -> dead
  -> 玩家点击怪物提交 combat.basicAttack 或 skill.cast（仅意图）
  -> Room 校验会话/协议/序号/限频/幂等
  -> CombatWorld 校验距离、冷却、法力、目标存活
  -> 服务端 RNG 计算命中/暴击/伤害
  -> 更新内存 HP/MP/冷却/怪物状态
  -> 生成 CombatEvent -> Room 广播 -> 客户端播放伤害数字/动作/死亡/刷新
  -> 节流 checkpoint 继续把 HP/MP/位置写入 PostgreSQL
```

阶段 4 不实现经验、等级成长、掉落、背包、装备、金币、PK、安全区或复活惩罚；
这些属于阶段 5/6。

## 3. 目标与范围

### 3.1 本阶段完成

1. 新建 `packages/game-domain`：战斗属性、命中/暴击/伤害纯函数、技能与怪物
   目录、无 IO 的 `CombatWorld`。
2. 两种怪物：`wild_slime`（野地史莱姆）与 `forest_wolf`（森林狼），各带等级、
   HP、攻击、防御、命中、暴击、攻击间隔、移速、仇恨、脱战、巡逻半径与刷新时间。
3. 怪物 FSM：`idle → patrol → chase → attack → return → dead`，死亡后按刷点
   重生，重生事件带满 HP 与位置。
4. 战士：普攻 + `warrior_heavy_strike`（重击）；法师：`mage_fireball`
   （火球术）；道士：`taoist_heal`（治愈术）。全部由服务端裁定。
5. 服务端权威：攻击距离、攻击间隔、技能冷却、法力消耗、目标存活、怪物 HP。
6. 服务端 RNG 注入：生产使用 crypto 种子；测试使用可控 RNG；同一 seed 与输入
   产生完全一致的事件流。
7. CombatEvent：`attack`、`hit`、`miss`、`heal`、`death`、`spawn`、`respawn`。
8. 玩家死亡与复活：3 秒后在同一地图出生点满 HP/MP 复活（MVP 策略）。
9. 怪物与玩家共用 AOI：`WorldState.monsters` 使用 `.view()`，远处怪物不下发。
10. 客户端：怪物渲染、点击选怪/普攻、目标面板、技能栏与冷却、伤害数字、受击/
    死亡/重生表现、战斗日志。
11. 野外刷点从 2 个扩展到 6 个（3 史莱姆 + 3 森林狼）。
12. 双浏览器 E2E 验证同一怪物权威 HP、技能消耗、死亡与重生。

## 5. 关键技术决策

1. **战斗规则与怪物运行时归 `game-domain`**：Room 只做适配；导航格、寻路、
   RNG、复活点通过参数注入，因此 game-domain 只依赖 contracts（ADR-019）。
2. **固定 RNG 抽取值**：每次攻击固定消耗 3 个随机数，命中与未命中的后续序列一致，
   使回放可复现。
3. **命令幂等按 commandId 重发原事件**：客户端按 `eventId` 去重；重试不会再次
   造成伤害。
4. **怪物与玩家共用 AOI**：不新增第二套兴趣管理；`WorldState.monsters` 使用
   `.view()`。
5. **玩家死亡/复活的 MVP 策略**：同地图出生点 3 秒满状态复活；不持久化死亡
   位置，checkpoint 写回 HP 0 后由下次加入恢复。
6. **断线玩家不可被新选为目标**：宽限期内不会被怪物击杀，重连后恢复。
7. **经验/掉落延后**：阶段 4 的击杀只产生权威 `death` 事件，不发经验或物品；
   客户端因此没有可伪造的经验结果。
8. **摄像机上移**：底部战斗 HUD 与旧布局冲突，上移 200px 保证点击目标不被遮挡。

## 9. 问题与解决

1. **底部战斗 HUD 遮挡近身怪物点击**：第一次 E2E 的 canvas 点击落在
   `.panel-heading` 上，未触达 Phaser；把摄像机焦点上移 200px，使玩家和近身
   怪物位于 HUD 之上。
2. **玩家尚未走到目标格就点击**：E2E 只等待怪物列表出现；补充等待自身权威
   tile 与摄像机稳定，避免攻击距离不足导致的合法拒绝。
3. **两名玩家站位过远**：怪物追击其中一人后，另一人超出 1.4 格射程；E2E 改为
   两名玩家都站在刷点上，并用真实攻击重试确认 HP 变化。
4. **击杀未计入指标**：击杀由命令路径产生，不在 tick 事件路径；把击杀/死亡
   统计抽到 `recordCombatOutcomes`，命令与 tick 两条路径共用。
5. **宽限期玩家被怪物攻击**：给 `CombatWorld` 增加 `targetable` 标记，断线即
   取消被选资格，重连恢复。
6. **编译产物格式化差异**：`maps:compile` 后执行 `pnpm format`，避免整文件
   格式抖动。
7. **负载脚本未处理 `combat.profile`**：注册空处理器，消除 SDK 告警。
