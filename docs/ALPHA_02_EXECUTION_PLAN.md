### 0.3 对路线的复核意见

`PROJECT_ROADMAP.md` 的 Alpha 0.2 范围整体成立，但执行顺序调整如下：

- **把商店/金币消耗端提前到第一个切片。** 当前金币只增不减，装备与补给没有
  决策空间；这是“30 分钟闭环”最短的短板，也是后续交易/拍卖的基础。

- **怪物威胁与死亡代价放在第三个切片。** 依赖职业差异，否则“变危险”只会变成
  “更容易死”。
- **美术与 HUD 持续并行**，但第一个切片只做必要的商店面板与可读性，不阻塞
  玩法验证。
- **性能优化与容量复测作为贯穿项**，在切片之间执行，不单独占一个玩法切片。

## 3. 切片 1：主城杂货商与经济闭环

### 3.1 产品目标

让玩家在第一次回城时做一次真实决策：把有限的金币花在药水还是护甲上；让打怪
产出的材料有稳定出售价值；让金币成为有意义的资源，而不是只增不减的计数。

### 3.2 范围

- 主城杂货商 NPC 可交互：靠近后打开商店。
- 商店出售：金创药、魔法药、布衣、皮甲（价格由内容 bundle 决定）。
- 商店收购：玩家背包内所有 `sellPrice > 0` 的物品（含材料、多余装备）。
- 购买/出售均为服务端权威事务：金币、账本、物品实例同事务；幂等键；行锁。
- 新角色获得 50 金币启动资金，保证第一次回城即可参与经济。
- 客户端：商店面板（购买/出售两个页签）、金币显示、距离不足提示。
- 物品价格进入内容 schema，运营可在内容工作台调整并发布。

### 3.3 非范围

- 不做任务、修理、仓库、摆摊、玩家交易、拍卖行。
- 不做动态库存/限购/税率/声望折扣。
- 不做图标美术（切片 4）。
- 不引入新数据库表；复用 `wallets`、`currency_ledger`、`asset_commands`、
  `item_instances`。

### 3.4 契约与数据

- `ItemContent` 增加可选 `buyPrice`、`sellPrice`（0 表示不售/不收）。使用
  `.optional()` 而不是默认值，避免改变历史 Release 的 checksum（EL-004）。
- 编译地图 NPC 增加可选 `role`（`merchant` / `guard`）；`starter_town` 的
  杂货商标记为 `merchant`。
- 新增 Client → Server：`shop.buy`、`shop.sell`；Server → Client：
  `shop.catalog`。
- `assetCommandKind` 增加 `shop_buy`、`shop_sell`；`asset.result` 复用。
- 新增拒绝码：`SHOP_UNAVAILABLE`、`INSUFFICIENT_GOLD`、`CANNOT_SELL`、
  `NOT_SOLD_HERE`、`INVALID_QUANTITY`。
- 校验：数量 1–99；非堆叠物品数量必须为 1；价格由服务端读取；客户端不能提交
  价格或金币结果。

### 3.5 服务端

- `AssetService.buy`：锁定角色与钱包，原子扣减金币；写账本
  （`reason='shop_purchase'`，幂等键含角色与 commandId）；按堆叠规则入包；
  背包不足整体回滚。
- `AssetService.sell`：锁定物品实例与角色；校验归属与可售价格；扣减/删除物品；
  原子增加金币并写账本（`reason='shop_sale'`）。
- Room：命令走 `runAssetCommand`；校验玩家存活、与 `merchant` NPC 距离
  ≤ 3 格；商品必须存在且 `buyPrice > 0`，收购必须 `sellPrice > 0`。
- 加入世界后发送 `shop.catalog`：本图商人位置、可购商品与收购价；只发送与
  玩家职业兼容的商品（无职业限制或职业匹配）。
- 指标：商店购买/出售计入现有资产命令、失败与拒绝码指标；金币流动以
  `currency_ledger` 的 `shop_purchase`/`shop_sale` 为准。独立的买卖计数留到
  Beta 经济看板统一增加，避免为单个玩法扩展指标结构。

### 3.6 客户端

- 玩家靠近商人时 HUD 显示“杂货商”入口；点击打开商店面板。
- 购买页：名称、价格、属性/回复、等级需求；“购买”按钮。
- 出售页：背包中可售物品、单价、数量；“出售”按钮。
- 金币与背包在 `asset.result` 后立即刷新；失败显示 Toast。
- 商店面板与背包/战斗面板分层，不遮挡关键战斗信息。

### 3.7 测试与验收

- 契约：数量边界、非法字段、价格不可由客户端提交。
- 领域：购买总价、出售总价、非堆叠数量校验。
- 应用集成（真实 PostgreSQL）：购买成功与账本、金币不足、背包满回滚、
  重复 commandId、并发购买不超扣、出售堆叠部分/全部、不可售物品、非本人
  物品被拒绝。
- 服务端集成：远离商人拒绝、靠近成功、目录按职业过滤、目录价格来自内容。
- E2E：新角色 50 金币 → 走到杂货商 → 买药水（金币减少、背包增加）→ 打怪
  获得材料 → 回城出售（金币增加）→ 买皮甲受等级限制的提示。
- 门禁：`pnpm verify`、隔离 E2E、`pnpm verify:invariants`、50 人容量回归
  （商店不劣化 tick 与资产 p95）。
- 证据：`docs/phase-reports/alpha-02/shop/`（截图、日志、压测、数据库）。

### 3.8 风险与对策

| 风险                       | 对策                                                       |
| -------------------------- | ---------------------------------------------------------- |
| 金币重复/负数              | 钱包条件更新 + CHECK + 账本同事务 + 并发测试               |
| 背包满时已扣金币           | 单事务：先校验入包位，失败整体回滚                         |
| 客户端伪造价格/数量        | 只接受 templateId/itemId/quantity；价格与金币由服务端算    |
| 历史 Release checksum 变化 | 新字段用 `.optional()`；用历史 payload 做 checksum 回归    |
| 商店让资产队列更慢         | 复用队列并观测 p95；恶化则按 TD-SRV-03 拆玩家命令并发      |
| 内容价格误配               | 价格范围校验 + 发布差异预览；后续接入经济合理性告警（0.4） |
