# Web Legend MVP 之后的研发路线（Alpha → Beta）

- 日期：2026-11-25
- 基线：MVP 阶段 0–9 已交付；审计结论见 `docs/MVP_ACCEPTANCE_REPORT.md`
- 产品评审：`docs/GAMEPLAY_REVIEW.md`
- 债务清单：`docs/TECHNICAL_DEBT.md`
- 估算口径：1 名全职全栈工程师 + 0.5 名美术，2 周一个迭代；人周为净开发量，
  不含等待与返工

## 0. 路线原则

1. **先修可信度，再加内容。** CI/E2E/容量证据不成立时，不进入 Alpha 0.2。
2. **先做手感，再做系统数量。** 自动攻击、职业差异、怪物威胁优先于公会/副本。
3. **每个版本必须有可玩的纵向切片和量化验收**，不以“页面完成”计。
4. **扩展性由指标触发。** 在多区服/多进程的真实需求出现前，不引入 Redis
   Presence、消息队列或服务网格（ADR-006、ADR-007）。
5. **内容生产工具与玩法同步演进。** Beta 前，新怪物/物品/技能应尽量只改内容
   数据，不改代码。

## 1. 版本总览

| 版本      | 主题                | 周期     | 净工作量 | 优先级 | 进入条件                    |
| --------- | ------------------- | -------- | -------- | ------ | --------------------------- |
| Alpha 0.1 | 可信度与体验止血    | 2 周     | 4 人周   | P0     | MVP 审计完成                |
| Alpha 0.2 | 游戏体验完善        | 6 周     | 12 人周  | P1     | 0.1 门禁通过                |
| Alpha 0.3 | MMORPG 核心玩法扩展 | 10–12 周 | 20 人周  | P1     | 0.2 验收通过                |
| Beta 0.4  | 内容生产与运营体系  | 8–10 周  | 18 人周  | P1     | 0.3 留存/稳定性达标         |
| 长期      | 多区服与规模化      | 按触发   | 待评估   | P2     | 单进程/单图容量出现真实瓶颈 |

## 2. Alpha 0.1：可信度与体验止血（2 周）

### 产品目标

让“MVP 已完成”这句话可被 CI 和真实数据证明；同时修掉最伤手感的两处体验
问题，为 0.2 的玩法迭代提供干净基线。

### 范围

- 自动攻击循环：锁定目标后按服务端冷却自动攻击；客户端显示攻击条；手动点击
  仅用于重新锁定（TD-CLI-01）。
- 拒绝提示改为自动消失的 toast，不再遮挡战斗面板（TD-CLI-02）。
- 封禁/踢下线不再进入可重连宽限；重连时重新校验账号状态（TD-SRV-04）。
- 内容发布前校验物品模板覆盖，避免删除物品导致登录事故；未领取掉落逐条容错
  （TD-DATA-04）。
- 击杀奖励按装备后属性裁剪/持久化（TD-DATA-01）。
- E2E 使用专用数据库/栈，CI 增加 PostgreSQL service 并真正执行 E2E
  （TD-OPS-01/02）。
- 把已通过的 50 人 × 10 分钟容量场景接入回归门禁（TD-QA-01），输出 tick/
  内存/带宽/拒绝码趋势。
- 开始拆分 `WorldMapRoom`：先抽会话/命令守卫/视图同步，保持行为不变
  （TD-SRV-01 第一阶段）。

### 技术任务

1. `worldMapRoom` 增加 `autoAttack` 状态机（服务端仍是唯一冷却裁定者；客户端
   只循环提交意图，重复 commandId 不重复结算）。
2. 客户端 `notice` 改为队列 + 定时清除；战斗面板 z-index 分层。
3. 管理断开使用显式 `terminated` 标记；`onReconnect` 查询 `accounts.status`。
4. 内容发布服务增加“模板引用完整性”校验：候选 bundle 必须覆盖当前
   `item_instances.template_id` 的 distinct 集合；否则阻断并列出影响角色数。
5. `WorldMapRoom` 抽出 `CommandGuard`（会话/协议/序号/限频/幂等）与
   `SessionRegistry`，三套命令管线复用。
6. CI：e2e job 加 `services.postgres` 与 env；`playwright.config.ts` 支持
   `E2E_DATABASE_URL`，webServer 建库/迁移/销毁；E2E 不再写开发库。
7. 压测脚本增加窗口指标、拒绝码分布与接受率断言。

### 依赖

- 无新架构决策；不新增数据库表（除必要的索引/字段）。
- 美术不参与。

### 里程碑

- D+3：自动攻击与提示改造合并，E2E 回归通过。
- D+7：CI E2E 绿灯；封禁重连/内容删除两条安全用例通过。
- D+10：50×10min 场景接入回归；Room 拆分第一阶段合并。
- D+14：0.1 门禁评审。

### 验收标准

- `pnpm verify` 与 CI 全部通过；E2E 在 CI 中真实执行 20/20。
- 50 人 10 分钟：0 资产失败、0 重复/丢失不变量、tick p95 ≤ 10ms、内存无
  持续增长（首尾差值 < 10%）；本轮实测 tick p95 8.79ms（单次基线）。
- 封禁后携带旧 token 重连失败；删除被持有物品的 Release 无法发布。
- 自动攻击下击杀一只史莱姆只需 1 次锁定点击。
- 无 P1 债务未关闭（Room 拆分可跨到 0.2，但第一阶段必须完成）。

### 风险

- 自动攻击与现有命令幂等/序号交互：用重复 commandId 与重连场景覆盖。
- E2E 独立库增加 CI 时长：并行 job、缓存 pnpm、保留 20 分钟超时。
- Room 拆分引入回归：只做行为等价抽取，先补集成测试。

## 3. Alpha 0.2：游戏体验完善（6 周）

> 执行状态（2026-11-25）：切片 1“主城商店与经济闭环”已交付；后续顺序调整为
> 商店 → 三职业 → 怪物威胁/死亡代价 → 装备与美术，理由见
> `docs/ALPHA_02_EXECUTION_PLAN.md` §0.3。

### 产品目标

让新玩家在 30 分钟内“有事做、有成长、有危险”，并让三个职业玩起来明显不同。
这是从“技术原型”变成“可对外测试的 Alpha”的关键版本。

### 玩法范围

1. **操作与战斗**
   - 自动攻击 + 攻击条 + 技能冷却条；目标锁定/取消；键盘八方向短步与停止。
   - 本地移动预演（ack 后立即走，服务端校正），公网手感可接受。
   - 死亡代价：损失少量当前经验（不降级），复活点复活；保护新手 10 级前。
2. **三职业**
   - 每职业 3 个技能（1 级/5 级/10 级解锁），至少 1 个位移/控制/持续效果。
   - 法师：MP 自然回复/冥想；道士：毒符 DoT + 治愈，明确定位；战士：冲锋/
     嘲讽/减伤。
   - 三套职业外观、攻击/施法/受击/死亡动画。
3. **怪物与地图**
   - 4–6 种普通怪（近战快慢、远程、群居）+ 1 个精英；等级 1–15。
   - 狼增加扑击/短冲刺；怪物技能预警；受击硬直。
   - 野外扩为 3 个区域（草原/密林/废墟），主城加可交互杂货商（买卖/修理）。
4. **装备与经济**
   - 15–20 件装备，覆盖 1–15 级、三职业、普通/精良两档；武器与防具都可掉落。
   - 金币消耗端：商店药水/修理/回收材料；材料可出售。
   - 背包图标、品质色、装备对比、排序、丢弃、出售。
5. **HUD 与美术**
   - HUD 重排：战斗区最大化、面板可折叠、提示 toast、提高对比度/字号。
   - 正式 tileset（草地/土路/石墙/水/树/建筑）与怪物造型；环境音与区域音乐。
   - 删除“阶段 6”等内部标签。

### 技术任务

- `content-schema` 扩展技能效果：`dot`、`dash`、`taunt`、`shield`、`manaRegen`
  的 Effect DSL 白名单与校验；怪物技能配置。
- 客户端动画状态机（待机/行走/攻击/施法/受击/死亡），与 `combat.event` 对齐。
- 商店事务：金币扣减 + 账本 + 物品入包/出包，单事务、幂等键、行锁；新增
  `shop_purchases` 或复用 `asset_commands`。
- 装备/背包 UI 重构；物品图标资源管线（manifest 增加 icon）。
- 死亡经验扣减进入资产事务；复活点与保护规则内容化。
- 压测扩展到新怪物/技能/商店交易；客户端 FPS 预算与 HUD profiler。

### 依赖

- 0.1 的自动攻击、命令管线与内容发布校验。
- 美术资源先行 2 周（tileset/角色/怪物/图标）。

### 里程碑

- 第 2 周：自动攻击/键盘/死亡代价；三职业技能框架。
- 第 4 周：新怪物/地图/商店/装备掉落；美术第一版。
- 第 6 周：HUD/动画/音效；5 名外部测试者 30 分钟试玩与问卷。

### 验收标准

- 3 个职业在 10 级时技能组合、输出方式、生存方式明显不同（试玩访谈可辨）。
- 1–15 级内容完整：玩家不会在 5 分钟后“无怪可打/无装备可追”。
- 金币有稳定消耗端；连续游玩 2 小时金币不无限膨胀。
- 新玩家 30 分钟内完成“创建→打怪→掉落→装备→商店→再成长”闭环。
- 50 人 10 分钟压测通过；客户端平均 FPS ≥ 45（普通独显/集显笔记本），
  软件渲染环境不作为验收基线。
- E2E 覆盖自动攻击、商店、死亡惩罚、三职业技能。

### 风险

- 美术产能是最大瓶颈：先做可复用的 tile 套件与三套角色，不做一次性场景。
- 新增 Effect DSL 可能让战斗复杂化：保持白名单与纯函数，禁止脚本执行。
- 经济改动引入刷金漏洞：所有商店/回收走资产事务与账本，补并发测试。

## 4. Alpha 0.3：MMORPG 核心玩法扩展（10–12 周）

### 产品目标

建立“玩家为什么每天回来”的核心：目标链、组队合作、玩家间经济与竞争。

### 玩法范围

1. **NPC 与任务**
   - 主城/野外 NPC 对话、商店、任务发布与交付。
   - 10–15 步主线（1–20 级）+ 5 个日常/循环任务；任务奖励经验/金币/装备。
2. **Boss 与副本**
   - 1 个野外精英 Boss（多人争夺）+ 1 个 3 人副本（2 个 Boss，阶段技能）。
   - 副本独立实例、进入条件、复活规则、掉落分配。
3. **组队与社交**
   - 组队（经验/掉落分配、队伍聊天、队长转移）；好友；公会（创建/加入/
     公告/成员权限）；聊天频道（世界/队伍/公会/私聊）。
4. **交易与经济**
   - 玩家面对面交易（双确认、事务、防诈骗）；主城拍卖行或摆摊的最小版本；
     金币回收与材料需求形成闭环。
5. **PK 与竞争**
   - 决斗开关、野外 PK 奖励/惩罚（先做轻度：击杀获得少量荣誉，不爆装）；
     排行榜（等级/击杀/Boss）。
6. **运营支撑**
   - 后台可查询任务/公会/交易/排行榜；封禁/禁言历史与申诉记录。

### 技术任务

- 动态 Room/实例：副本按队伍创建 `dungeon:<template>:<instance>`，匹配与
  销毁；可能需要 ADR（动态实例路由、房间注册、断线恢复）。
- 任务状态持久化（`character_quests`）、任务 DSL/内容 schema、进度事件
  （击杀/拾取/对话/到达）。
- 组队/公会/好友表与事务；聊天频道与持久化/审核；交易双人锁与账本。
- Boss 阶段 AI 与技能预警；副本掉落分配（队长分配/需求贪婪的最小版本）。
- 拍卖/摆摊的经济防护：价格上下限、税率、并发扣款、审计。
- 后台：社交/任务/交易查询与审计，RBAC 细分。

### 依赖

- 0.2 的战斗/内容/商店/装备体系。
- 动态实例可能需要 Redis Presence（仅当多进程）；单进程先用内存注册表，
  写 ADR 说明触发条件。

### 里程碑

- 第 3 周：任务系统与 10 步主线；NPC 对话/交付。
- 第 6 周：组队/好友/聊天频道；副本实例与第一个 Boss。
- 第 9 周：公会/交易/拍卖最小版；PK 与排行榜。
- 第 12 周：3 人副本全流程、经济压力测试、运营后台。

### 验收标准

- 3 人组队可完成副本，掉落分配无重复/丢失；断线可重连回副本。
- 玩家交易 1,000 次压测无复制/丢失金币或物品；审计可追溯。
- 任务链 10 步可完成，进度在重登/崩溃后正确恢复。
- 公会创建/加入/权限/解散可用；聊天频道过滤与限频有效。
- 30 天留存试玩（20–50 人）有可分析数据；无 P0/P1 经济漏洞。

### 风险

- 范围最大，容易延期：按“任务→副本→组队→交易→公会→PK”顺序，每两周
  一个可验收切片，不做大爆炸发布。
- 经济系统是作弊重灾区：交易/拍卖必须事务化 + 账本 + 限额 + 审计。
- 社交带来内容审核压力：聊天持久化、举报、禁言历史必须同步上线。

## 5. Beta 0.4：内容生产与运营体系（8–10 周）

### 产品目标

让非技术运营可以持续生产内容、做活动、看数据、处理玩家问题，而不依赖开发
发版。

### 范围

1. **内容工作台 2.0**：逐字段表单（怪物/物品/技能/掉落/任务/商店），草稿
   冲突检测、审批流、差异对比、定时发布、按 Realm 草稿。
2. **资源管线**：图标/贴图/音效上传、尺寸/格式校验、manifest 版本、CDN/
   对象存储接入；资源回滚。
3. **运营活动**：双倍经验/掉落、限时 Boss、节日活动、邮件补偿；活动日历。
4. **数据分析**：DAU/留存/在线时长/等级分布/经济流入流出/掉落分布/任务
   完成率；异常检测（金币异常、刷怪异常）。
5. **客服与安全**：玩家查询、禁言历史/申诉、交易回溯、异常账号标记；后台
   MFA/OIDC、会话管理、细粒度 RBAC、登录审计。
6. **交付与运维**：独立 Outbox worker、审计/Release 归档、CI 构建镜像与
   部署演练、备份校验、告警修复。

### 技术任务

- 内容 schema → 表单渲染器（JSON Schema 驱动或手写每类表单）；保存前校验。
- 资源上传服务与对象存储抽象；生产 manifest 签名/版本。
- 活动调度器（定时激活/结束，写审计）；邮件/补偿走资产事务。
- 分析事件管道（先 PostgreSQL 物化视图，量级上升再评估 ClickHouse）。
- 管理端安全加固（MFA、会话撤销、登录审计、IP 白名单）。
- CI 增加镜像构建、compose 冒烟、prod-check、备份恢复演练；部署脚本自动
  迁移/备份。
- 审计/Outbox/掉落/命令历史归档与保留策略。

### 依赖

- 0.3 的任务/交易/公会数据模型。
- 对象存储可用（S3 兼容）；否则先用本地卷并标注限制。

### 里程碑

- 第 2 周：内容表单 1.0（怪物/物品/掉落）与审批流。
- 第 5 周：活动调度、邮件补偿、分析看板 1.0。
- 第 8 周：资源管线、客服工具、MFA、CI 交付门禁。
- 第 10 周：一次真实运营活动演练（发布→活动→回滚→复盘）。

### 验收标准

- 非技术运营在无开发参与下完成“新增怪物+掉落+活动+公告”并发布/回滚。
- 活动可定时开始/结束；邮件补偿不重复发放；审计完整。
- 分析看板能回答 DAU、7 日留存、金币产出/消耗、等级分布。
- 生产部署、镜像构建、备份恢复、告警在 CI/演练中自动验证。
- 后台无任意 SQL/JS 执行路径；所有写操作审计。

### 风险

- 表单化编辑器工作量大：先覆盖高频类型（怪物/物品/掉落/任务），低频仍可
  JSON 高级模式。
- 分析管道过度设计：先用 PostgreSQL，按数据量阈值再升级。
- 活动配置错误影响经济：活动必须走 Release/审批/回滚与限额。

## 6. 长期演进（按指标触发）

### 6.1 多区服与多 Game Server

**触发条件**：单地图同时在线持续 > 50，或单进程 CPU/事件循环 P99 超过预算，
或需要按地区隔离。

**演进**：实例注册表 → 连接路由/网关 → 多进程按 Realm 拆分 → Redis
Presence/Driver → 跨服聊天/排行榜。每一步写 ADR，先做双进程演练，不直接上
Kubernetes/Kafka。

### 6.2 多地图实例与线路

**触发条件**：热门地图拥堵或副本数量增长。

**演进**：动态 Room 命名与匹配、线路切换、实例回收、AOI 事件过滤、副本
生命周期管理；必要时引入匹配服务。

### 6.3 大型多人玩法

**触发条件**：公会战/攻城等 100+ 同屏需求出现。

**演进**：空间分区与 tick 预算、事件批处理、战斗事件 AOI、专用战斗实例、
压测目标从 50 提升到 200+；先做技术预研与原型，不提前重构。

### 6.4 客户端与表现
