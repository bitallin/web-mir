# ADR-033：物品图标由资源 manifest 提供，并统一品质呈现

- 状态：Accepted
- 日期：2026-11-26
- 阶段：Alpha 0.2 S4（图标与品质）
- 关联：ADR-020（资产事务）、ADR-022（内容发布）、ADR-026（商店）、
  ADR-029（角色动画资源与 manifest）、ADR-032（装备品质与对比）、
  TD-CLI-13（正式美术）、TD-CLI-14（商店面板遮挡）

## 1. 背景

S4-A 后背包、装备槽与商店都以纯文字行展示物品，只有稀有品质有金色描边。
装备从 5 件增长到 17 件、再随废墟切片的 9–10 级装备增长到 30 件以上后，玩家在
背包与商店里需要逐行读名称才能区分物品；掉落列表同样只有文字。S4 的范围明确
包含“背包图标、品质色统一”（`docs/ALPHA_02_EXECUTION_PLAN.md` §4）。

正式美术尚未到位（TD-CLI-13）。现有角色与 tileset 已采用“程序生成占位资源 +
manifest 描述 + 可复现生成脚本”的方式，图标应沿用同一模式，而不是等正式美术
才开始。

## 2. 问题

1. 物品没有图标，背包/商店/装备槽/掉落列表的扫读成本高，品质差异只在背包里
   有表现，商店与装备槽没有。
2. 图标若直接写进内容 Release，会带来内容 checksum 变化、发布流程与美术迭代
   耦合（EL-004/EL-023）。
3. 内容会持续新增物品；图标缺失时客户端必须仍能安全渲染。
4. 商店目录 DTO 没有品质字段，无法与背包使用同一套稀有样式。
5. 图标资源必须是可复现的占位资源，并明确标记为占位，不能伪装成完成品。

## 3. 备选方案

1. **把 `icon` 字段放进 `ItemContent`。** 每次新增/替换图标都要发布内容
   Release，并与历史 checksum、运营草稿耦合；资源版本应由 manifest 管，而不是
   内容数值。
2. **纯客户端按 `kind` 生成图形（无资源文件）。** 实现最轻，但无法在未来替换
   为正式图标，也无法为单个物品保留独立造型，最终仍要重做。
3. **每个物品一个 PNG。** 简单直观，但 37+ 个请求/文件与 manifest 维护成本高，
   与现有单图集（tileset/角色）风格不一致。
4. **单张方格格子图集 + manifest 模板映射 + 生成脚本（采纳）。** 与 ADR-029
   的资源管线一致，客户端一个 URL、CSS 定位；模板缺失时按 kind 与通用图标
   回退。

## 4. 决策

1. `AssetManifest` 增加必填 `itemIcons`：
   - `style: 'procedural-placeholder'`（明确标记占位）；
   - `image`、`size`、`columns`、`rows`；
   - `templates`：模板 id → 图集帧；
   - `kinds`：四种物品类型各自的回退帧；
   - `fallback`：未知类型的通用帧。
     Schema 校验所有帧都落在图集格子内；图集版本写入 manifest，不进入内容
     Release。
2. 图标由 `content/assets/generateItemIcons.ts` 生成：按物品族（剑/斧/法杖/
   护甲/药水/材料等）绘制 32×32 程序化图标，每个模板有独立配色；脚本从
   `BASE_CONTENT_BUNDLE` 读取全部物品 id，缺图标直接失败，并在 manifest 映射与
   生成结果不一致时打印期望 JSON 并退出非零。`raster.ts` 与角色生成器共用像素
   画布与 PNG 编码，角色贴图逐字节保持不变。
3. 客户端解析顺序固定为“模板 → 类型 → 通用”。图标是纯展示：服务端仍只下发
   `templateId`/`kind`，不参与掉落、属性或库存判断。
4. 图标用于背包、装备槽、商店购买/出售与“附近掉落”列表；Phaser 地面掉落物
   标记本轮不改，留给表现层后续切片。
5. `ShopOffer.quality` 增加可选字段（缺省 `common`），服务端从内容快照读取。
   商店、装备槽与背包共用同一稀有样式（金色描边 + “稀有”标签）；品质仍只影响
   展示（ADR-032）。
6. manifest 版本升到 `alpha0.2.2`，三张编译地图重算（编译产物内嵌资源版本）；
   无内容 Release、无数据库迁移、无协议破坏性变更。

## 5. 影响

- 新增物品只需在生成器加入条目并运行 `pnpm assets:generate`；正式图标到位时
  可替换图集 PNG 与 manifest 映射，客户端无需改代码。
- 新内容若先于图标上线，客户端按 kind 显示回退图标，不会出现空方块。
- 商店 DTO 增加可选字段；旧服务端（缺字段）下客户端把品质视为 `common`。
- 资源 manifest 变更需要重编译地图；本轮已重编译并提交产物。
- 未处理：地面掉落物在场景中的图标、正式图标美术、装备槽扩展、丢弃物品。

## 6. 验收

- 契约：图集帧越界被拒绝；缺任一 kind 回退帧被拒绝；商店品质接受
  `common`/`rare`，拒绝未知值。
- 单元：模板优先、kind 回退、通用回退与图集定位；全量 448 测试通过。
- E2E：背包三组初始物品均有图标且帧号与 manifest 一致；装备后武器槽图标不变；
  商店购买/出售每一行都有图标；掉落行有图标。34/34 通过。
- 真实浏览器：8584 新角色背包 3 个图标（帧 35/19/20），商店 9 个商品图标；
  证据 `docs/phase-reports/alpha-02/icons/`。
- 未验证：稀有物品在真实浏览器中的描边/标签（无稳定获取路径，与 S4-A 相同）。
