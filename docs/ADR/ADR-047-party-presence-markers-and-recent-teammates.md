# ADR-047：队伍世界标记与「最近同玩」

- 状态：Accepted
- 日期：2026-11-28
- 阶段：Alpha 0.3 S4-E 队伍在场感切片
- 关联：ADR-035/036（组队与进程级 PartyService）、ADR-044（队伍聊天与权限）、
  ADR-045（好友与跨图邀请）、ADR-046（在线目录与私聊）、TD-CLI-17、
  TD-SRV-11、路线图 4.3“组队与社交”

## 1. 背景

S4-A 到 S4-D 已交付队伍聊天、移交、踢人、好友、私聊与到达目标世界标记。
队伍跨图保留之后，玩家能看到队伍名单，却看不到队友在世界里的位置；离开
队伍、分开练级或下线再上线后，也没有入口重新邀请刚一起玩过的人。

TD-CLI-17 剩余两项正是这两件事：世界内队伍成员标记，以及按名字邀请/最近
同玩入口。直接做“按名字搜索任意在线玩家”会带来枚举与骚扰面，当前版本没有
黑名单/举报体系承接。

## 2. 问题

1. **在场感**：队伍名单只有名字、等级、HP 与在线状态；同图队友没有视觉区分，
   小地图也无法快速找到队友。
2. **重新组队**：邀请只覆盖附近 15 格与好友；刚解散的队伍无法跨图重新邀请，
   除非双方先加好友。
3. **隐私边界**：按名字搜索会让任意玩家被枚举；需要一种只覆盖“已经一起玩过”
   的关系入口。
4. **状态归属**：队伍与在线状态是进程级、临时社交状态（ADR-036/046）；最近
   同玩是否值得进入 PostgreSQL，需要与资产/关系数据区分。
5. **公开状态**：队友标记不能通过公开 Room State 暴露“谁和谁组队”；名单必须
   继续只走私有消息。
6. **兼容**：旧客户端、旧快照、协议版本、内容与数据库不应被破坏。

## 3. 备选方案

1. **在 PlayerState 上增加 partyId 或队伍颜色**：任何客户端都能读到别人的队伍
   关系，泄露隐私；且违反“私有数据不进公开 Room State”。拒绝。
2. **全局按名字搜索在线玩家并邀请**：实现简单，但形成枚举与骚扰渠道，当前
   没有举报/黑名单/限频体系；拒绝。
3. **把最近同玩写入 PostgreSQL**：可跨重启保留，但队伍本身仍是进程内状态，
   会制造“有历史、无队伍”的半持久模型，并增加迁移与清理成本；本切片拒绝，
   保留为 Beta 社交持久化时的整体设计。
4. **新增 `social.recent` 协议与命令**：与好友快照重复，且需要再定义命令门禁；
   拒绝。
5. **客户端从私有队伍名单派生世界/小地图标记 + 进程级最近同玩并入好友快照 +
   最近同玩可跨图邀请**（采纳）。

## 4. 决策

### 4.1 世界与小地图标记由私有名单派生

- `PartyView` 仍是唯一来源；客户端把成员 id 交给 Phaser 场景与小地图，按
  `PlayerState.playerId` 在当前 AOI 内匹配。
- 世界内：同图、存活、非自己的队友脚下显示绿色椭圆环，名字改为绿色；自己
  保留金色名字与金色小地图环。跨图或不在 AOI 的成员不绘制标记。
- 小地图：队友使用绿色圆点与外圈；图例增加「队友」；输出
  `data-party-markers` / `data-party-ids` 供真实浏览器断言。
- 标记随名单、死亡、过图与场景重建更新；`WorldBridge` 保存最近名单并在场景
  重建时重放。服务端不新增字段，客户端不推断别人的队伍。

### 4.2 最近同玩记录在进程级 PartyService

- 队伍真正形成（`acceptInvite` 成功）时，`PartyService` 为所有成员两两记录
  `{ playerId, displayName, classId, level, lastPlayedAt }`；只发邀请未接受
  不产生记录。
- 每位玩家最多保留 `RECENT_TEAMMATES_MAX = 20` 条，超出按 `lastPlayedAt`
  淘汰最旧；记录只对当事人可见。
- 记录属于进程内存，与队伍、presence 一样在重启后消失（TD-SRV-15）。

### 4.3 私有快照携带最近同玩

- `friend.snapshot` 增加 `recent` 字段（最多 20 条，默认空数组，旧快照仍可
  解析）；在线状态、职业与等级优先使用当前 presence，离线时回退到记录值。
- 好友面板新增「最近同玩」区，显示名字、等级、在线状态与「邀请」；离线、
  已在队伍或队伍已满时禁用。没有全局搜索框。

### 4.4 邀请授权扩展

- 保留 ADR-035 的附近 15 格规则与 ADR-045 的好友跨图规则。
- 新增：曾经同队（`PartyService.knowsTeammate`）可在任意地图邀请。
- 最近同玩命中时跳过好友数据库查询；未命中仍按既有异步好友校验。
- 陌生人依旧返回 `PARTY_TARGET_UNAVAILABLE`，不泄露更多信息。

### 4.5 兼容与边界

- 无协议版本升级、无数据库迁移、无内容发布；`friend.snapshot` 新字段为加法。
- 最近同玩不提供离线消息、历史、黑名单或世界频道；这些仍属 TD-CLI-17 /
  TD-SRV-14 的后续范围。
- 队伍标记是纯表现层，服务端权威的战斗、拾取与任务不受影响。

## 5. 后果

1. 同图队友一眼可见，小地图能快速汇合；跨图成员仍只在名单中显示。
2. 解散后的队伍可以跨图重建，形成“一起玩过的人”这一最小社交回路，而不
   打开全局搜索的骚扰面。
3. 进程重启或换服会丢失最近同玩；需要跨重启时再评估与队伍持久化一起做。
4. 客户端多了一份按 id 匹配的展示逻辑；用真实浏览器断言标记数量、身份与
   跨图消失，避免只验证 DOM 面板。
5. 新增债务 TD-SRV-15（最近同玩仅进程内），与 TD-SRV-11/12/13 同类。

## 6. 验证

- 契约：快照缺省 `recent` 为空、上限 20、字段校验。
- 服务：只有接受邀请才记录、双向可查、超过 20 条淘汰最旧、邀请未接受不记录。
- 集成：真实 PostgreSQL + 两个真实 Room 完成组队→解散→好友快照出现最近
  同玩→成员过图→非好友跨图邀请成功。
- 浏览器：组队后双方小地图显示 2 个队伍标记、世界标记只含对方；解散后回到
  1/0；好友面板显示「最近同玩」并可从该入口重新邀请；过图后跨图成员不显示
  世界标记。证据见 `docs/phase-reports/alpha-03/ALPHA_03_PARTY_PRESENCE_REPORT.md`。
