# ADR-030：怪物攻击前摇与扑击预警

- 状态：Accepted
- 日期：2026-11-26
- 阶段：Alpha 0.2 S3（切片 1）
- 关联：ADR-019（战斗领域与怪物运行时）、ADR-022（内容发布）、ADR-028
  （状态效果事件）、TD-CLI-05；`docs/ALPHA_02_EXECUTION_PLAN.md` §4

## 1. 背景

S2 结束后，三职业有技能、法力与外观，但野外的威胁仍然只有“贴脸后按间隔造成
伤害”：史莱姆与森林狼的差异主要是数值，玩家在战斗中除了点选目标没有可做的
决策。S3 的目标是让野外变危险，并给玩家一个可学习、可反应的操作空间。

现有战斗事件（`attack`/`hit`/`miss`）在怪物开始攻击的同一 tick 就结算伤害，
没有“承诺 → 落地”的时间差；客户端即使想提示，也只能在伤害已经发生之后。

## 2. 问题

1. 需要一个“怪物已锁定、攻击尚未生效”的窗口，让玩家可以走位躲避。
2. 命中与否仍必须由服务端裁定；客户端不能因为“点了闪避”就免伤。
3. 服务端 tick 必须保持确定性：同一 RNG 种子与输入产生同一事件序列。
4. 历史内容 Release 不能因为新字段失效（EL-004）。
5. 不能为单个精英怪写死客户端逻辑，后续应能配置到任意怪物。

## 3. 备选方案

1. **客户端预测重击并自行免伤。** 手感直接，但破坏服务端权威，且无法防作弊。
2. **完整弹道 / 碰撞模拟。** 表达力强，但需要新的空间查询、网络同步与性能预算，
   与当前“格子 + 事件”的战斗模型不匹配。
3. **纯客户端视觉预警（不加协议）。** 改动最小，但预警时刻完全由客户端猜测，
   服务端不知道玩家是否真的躲开，只能按原逻辑必中，失去玩法意义。
4. **内容驱动的攻击前摇 + 服务端落点裁定（采纳）。** 怪物在攻击开始时提交
   落点，服务端在落点时刻判定目标是否仍在范围内。

## 4. 决策

### 4.1 内容字段

`monsterContentSchema` 增加两个可选字段：

```json
{
  "windupMs": 900,
  "windupRadiusTiles": 1.5
}
```

- `windupMs` 省略或为 0：沿用即时结算；历史 Release checksum 不变。
- `windupRadiusTiles` 省略时按 1.5 处理；仅在有前摇时有意义。
- 校验：设置了半径但没有前摇 → error；前摇不短于攻击间隔 → warning。

### 4.2 领域规则

- 攻击进入射程且冷却结束时，带前摇的怪物**冻结位置**并提交一次攻击：
  记录目标 ID、落点（提交时目标所在整数子格坐标）、半径与落地时刻。
- 提交时不掷任何 RNG；不存在“预警时已经命中”的情况。
- 落地 tick：
  - 目标已死亡、断线或不存在 → 本次攻击作废，不产生事件；
  - 目标与落点距离 > `windupRadiusTiles` → 产生 `miss`（闪避）；
  - 否则照常掷命中/暴击/伤害，产生 `attack` + `hit`/`miss`。
- 怪物死亡、重生会清除未落地的前摇；前摇期间怪物不追击、不重新选目标。

### 4.3 协议

新增 `combat.event` 变体（加法）：

```json
{
  "kind": "telegraph",
  "sourceId": "wilds_alpha_1",
  "sourceType": "monster",
  "targetId": "<characterId>",
  "targetType": "player",
  "x": 26500,
  "y": 4500,
  "radiusTiles": 1.5,
  "impactInMs": 900
}
```

- 只投递给能看见攻击者或目标的会话（与 `attack`/`hit` 一致）。
- `PROTOCOL_VERSION` 不变：新事件是加法，前后端同版本发布，旧客户端不会收到
  不认识的 `kind`（服务端与客户端同仓库同步部署）。

### 4.4 客户端

- 落地位置画红色范围圈，内部填充在前摇时长内由小到大展开，指示“何时落地”。
- 目标是自己时，战斗日志提示“蓄势扑击，快离开红圈”，并播放低音预警。
- 预警只是表现；客户端不参与命中判定。预警在落地后 120ms 内清除，怪物死亡时
  立即清除。
- 仅开发环境暴露 `activeTelegraphs()` 供 E2E 断言。

### 4.5 同切片的怪物生态

下列差异不引入新代码，只通过内容与现有 AI 参数表达：

| 怪物     | 定位     | 关键参数                                              |
| -------- | -------- | ----------------------------------------------------- |
| 毒牙蜘蛛 | 远程     | `attackRangeTiles: 3.2`，移速 1,600，攻击间隔 2.2s    |
| 石甲守卫 | 慢速重甲 | 生命 230、防御 10、移速 900、攻击间隔 2.6s            |
| 白狼王   | 精英     | 生命 320、攻击 18、`windupMs: 900`、攻击距离 2.6 扑击 |

## 5. 理由

- “提交落点 + 落地判定”把可闪避性放在服务端：玩家看到的是真实裁定结果，
  `miss` 事件也能复用现有的命中反馈与日志。
- RNG 推迟到落地，保证回放确定性；前摇阶段没有额外随机消耗。
- 可选字段与加法事件符合 EL-004 / EL-011：旧 Release 仍合法，旧 Room 行为不变。
- 远程与重甲怪物完全由内容参数表达，避免为每种“行为”新增枚举或分支。

## 6. 影响范围

- `contracts`：怪物内容可选字段；`telegraph` 事件。
- `content-schema`：前摇/半径校验与基线怪物、材料、掉落表。
- `game-domain`：`CombatWorld` 前摇状态机、落地判定与确定性测试。
- `game-server`：`telegraph` 按 AOI/归属投递；新增真实 PostgreSQL + Colyseus
  集成测试。
- `game-web`：预警圈渲染、日志/音效、诊断钩子、三种新怪物占位造型。
- `content/maps`：野外新增 6 个刷点（精英 1、蜘蛛 3、守卫 2），刷点总数 36。
- 运维：新增内容 Release `2026.11.26.3`（checksum `bd54ce8c…`）。

## 7. 部署约束

- 编译地图的刷点引用属于代码，怪物模板属于内容 Release；内容校验会把两者对齐。
  新增刷点时，必须同时发布包含对应怪物的 Release，否则旧 Release 会校验失败。
  `ContentStore` 在校验失败时保留上一个快照（启动时为基线 bundle），不会使用
  非法内容，但会持续报错；正确做法是先发布并激活新 Release，再让新 Room 使用。
- 旧 Room 仍固定创建时的内容快照（ADR-008/022）；激活后需要新 Room 才能出现
  新怪物与预警行为。

## 8. 未来调整条件

- 若需要“前摇可被控制技能打断”，在领域结果中增加 `interrupt` 事件与状态，
  而不是让客户端取消。
- 若预警范围需要非圆形（扇形/直线冲锋），扩展内容字段为形状描述；当前圆形
  足以覆盖扑击。
- 若同屏预警数量导致渲染压力，可限制同时显示数量或改为共享 Graphics；当前
  每个怪物最多一个预警。
