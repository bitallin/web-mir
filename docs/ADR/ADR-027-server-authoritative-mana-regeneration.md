# ADR-027：服务端权威、内容驱动的法力回复

- 状态：Accepted
- 日期：2026-11-25
- 阶段：Alpha 0.2 S2（任务 1）
- 关联：ADR-019（战斗领域）、ADR-022（内容发布）、ADR-025（tick 与命令管线）；
  `docs/GAMEPLAY_REVIEW.md` 3.3、`docs/ENGINEERING_LEARNINGS.md` EL-004

## 1. 背景

三职业各只有一个技能，且 MP 只减不回：法师 80 MP 只够 8 次火球，道士 60 MP
只够 5 次治疗，之后只能普攻。职业定位（法师持续输出、道士持续辅助、战士偶尔
爆发）无法成立，也让药水成为唯一的资源来源。

需要一种简单、可内容化、可测试的资源回复机制，为 S2 后续 DoT/位移技能提供
公共基础，同时不引入客户端计时或 tick 内 IO。

## 2. 决策

### 2.1 回复速率属于内容

`ClassContent` 增加可选 `mpRegenPerSecond`（0–100 的整数）。基线：

| 职业 | 每秒回复 | 依据                                |
| ---- | -------- | ----------------------------------- |
| 战士 | 1        | 重击 6 MP / 5s CD，技能是偶尔的爆发 |
| 法师 | 3        | 火球 10 MP / 3s CD，维持持续施法    |
| 道士 | 2        | 治疗 12 MP / 8s CD，维持持续辅助    |

字段使用 `.optional()`，旧 Release 缺少时按 0 处理，checksum 不变（EL-004）。

### 2.2 回复由固定 tick 推进

`CombatWorld.step(stepMs)` 为每个存活玩家累计毫秒余量，每满 1000ms 增加
`mpRegenPerSecond` 点，并封顶 `maxMp`。死亡、满蓝、速率为 0 时清空余量；
复活与改变 MP 的写回会重置余量，避免“积攒后爆发”；只改 HP 的消耗品不清空
余量，避免丢弃不足 1 秒的进度。

- 不使用客户端时间戳、不读取系统时钟，回放与压测可确定复现。
- 不产生战斗事件；MP 已由 Room 每 tick 同步到状态视图，客户端无需新增协议。
- 回复计算是 O(存活玩家数) 的纯内存操作，不增加 tick 内的 IO。

### 2.3 数值可由运营发布调整

回复速率随 Content Release 固定到 Room；新 Release 只影响之后创建的 Room
（ADR-008/022）。后台内容工作台可直接编辑该字段，校验只做范围检查。

## 3. 备选方案

| 方案                 | 未采用原因                                     |
| -------------------- | ---------------------------------------------- |
| 客户端本地回复并预测 | 违反服务端权威；重连/多端会不一致              |
| 仅脱战回复           | 需要额外的战斗状态与计时，首版收益不明确       |
| 按技能命中回复       | 让技能循环更复杂，且不利于道士治疗等非伤害行为 |
| 固定全局回复速率     | 无法体现职业差异，后续还要再改内容结构         |
| 用浮点每秒回复       | MP 是整数，浮点会引入累积误差与回放不一致      |

## 4. 影响

- 正面：法师/道士不再在几次施法后陷入只能普攻；职业资源节奏开始分化；为后续
  技能提供统一资源模型。
- 限制：当前是“始终回复”，没有脱战/冥想差异；数值是初始平衡，需要试玩校准。
- 风险：药水与回复叠加可能让高等级玩家过度续航；后续通过技能消耗、怪物压力
  与内容数值共同调节。
- 兼容：旧内容 Release 无回复；开发/生产需发布包含该字段的新 Release 才能
  生效。

## 5. 验收

- 法师 MP 0 → 1 秒后 3、3 秒后 9，最终封顶 80；战士 1/秒；道士 2/秒。
- 死亡期间不回复；复活回满；药水写回后无积攒爆发。
- 注入内容可改变速率；旧 payload 不注入默认值、checksum 不变。
- 确定性回放快照包含回复结果。
- 浏览器 E2E：法师施法后 MP 下降并自动回满。
