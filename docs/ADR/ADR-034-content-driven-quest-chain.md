# ADR-034：任务链由内容定义，进度与奖励走服务端资产事务

- 状态：Accepted
- 日期：2026-11-26
- 阶段：Alpha 0.2 S4-G（目标链）
- 关联：ADR-008（Room 固定内容快照）、ADR-011（效果白名单）、
  ADR-020（资产事务与幂等）、ADR-022（内容发布）、ADR-026（商店 NPC 距离）、
  ADR-031（死亡代价经验扣减）、TD-DATA-11（经验流水）、EL-022（新增内容
  section 的横切成本）

## 1. 背景

Alpha 0.2 交付了商店、三职业、怪物威胁、死亡代价、装备与三张地图，但玩家进入
世界后仍然没有“下一步做什么”：主城守卫只是一个不可交互的标记，击杀没有目标，
回城除了买卖没有理由。`docs/GAMEPLAY_REVIEW.md` 把“主城 2 个有功能的 NPC +
1 条最小任务链（引导玩家去野外）”列为 Alpha 0.2 的最小可玩目标；
`docs/PROJECT_ROADMAP.md` 把任务系统列为 Alpha 0.3 的第一个核心系统。

本切片先交付一条最小但真实的任务链，作为后续任务/Boss/副本的基础，而不是先
搭一套通用任务引擎。

## 2. 问题

1. **目标从哪里来？** 任务定义必须能被运营调整并随内容 Release 发布，不能写死
   在代码里；同时历史 Release 没有该 section 时必须继续可加载（EL-004）。
2. **进度谁来记？** 击杀在固定 tick 内发生，数据库写入必须异步；如果任务进度
   与击杀奖励分开提交，一次回滚或重试就可能出现“有奖励没进度”或“有进度没
   奖励”。
3. **奖励如何防重复？** 交任务必须像拾取/装备/商店一样：事务、行锁、幂等键，
   重复命令不能重复发经验、金币或物品。
4. **能否被伪造？** 客户端不能提交进度、奖励或“已完成”状态；接取/交付必须
   校验 NPC 距离、等级与前置任务。
5. **回滚会怎样？** 内容 Release 可以回滚，但玩家的任务记录不能因为回滚消失或
   变成可重复领取的漏洞。

## 3. 备选方案

1. **把任务写在代码里（常量表）。** 最快，但违反“内容与代码分离”，运营每次改
   数值都要发版；无法参与发布校验与差异预览。
2. **任务进度单独一张事件表，异步消费击杀事件。** 解耦彻底，但需要新增事件
   队列/消费者与去重策略；当前击杀奖励已经是串行资产事务，单独再加一条链路
   会放大不一致窗口，收益不足。
3. **完成即自动发奖，不要求回 NPC。** 实现更小，但任务链失去“回城交付”的
   完整循环，主城仍然只是商店；与产品目标不符。
4. **内容 section + `character_quests` 表 + 击杀奖励同事务推进 + 显式交付
   （采纳）。** 复用既有内容发布、资产事务、幂等命令与 NPC 距离模式。

## 4. 决策

1. **内容 section `quests`（可选）。**
   - `QuestContent` 字段：`id`、`title`、`description`、`giverNpcId`、
     `levelRequirement`、可选 `prerequisiteQuestId`、`objective`、
     `rewards`。
   - `objective` 是封闭白名单，v1 只有 `kill`（`monsterId`、`count`）。新增
     目标类型（收集/到达/对话）必须走代码发布，和技能 effect 白名单一致。
   - `rewards` 是 `exp`、`gold`、`items[]`；物品数量不得超过堆叠上限。
   - section 可选，历史 Release 不含 `quests` 时继续有效；基线内容提供三任务
     链。`content_section` 枚举通过 expand 迁移增加 `quests`。
   - 校验：NPC 必须存在于某张编译地图、前置存在且无循环、目标怪物存在、
     奖励物品存在、装备类奖励可被各职业获得（v1 只用通用材料/药水）。
2. **持久化 `character_quests`。**
   - 每角色每任务一行，`status` 为 `active | completed | claimed`，
     `progress`、`accepted_at`、`completed_at`、`claimed_at`、`version`。
   - 唯一约束 `(character_id, quest_id)`；CHECK 保证 `progress >= 0`、
     `completed_at` 与状态一致、`claimed_at` 只出现在 claimed。
   - 任务定义不复制进数据库：状态只引用内容里的 `questId`。回滚 Release 不会
     删除记录；新版本若移除该任务，记录保留但不再展示。
3. **进度写进击杀奖励事务。**
   - `AssetService.grantKillReward` 在同一个 PostgreSQL 事务里：锁角色、写击杀
     幂等行、结算经验/金币/掉落、推进所有匹配的活动任务、必要时标记 completed。
   - 事务提交后，Room 才向本人发送 `quest.update` 与“任务完成”提示；事务失败
     或重复击杀引用不会推进进度。
   - 任务目标按击杀者计算（`killerId`），不按伤害归属或同图他人。
4. **接取与交付是资产命令。**
   - 新增 `quest.accept` / `quest.claim`；`asset_commands.kind` 增加
     `quest_accept` / `quest_claim`。
   - Room 校验会话、存活、协议/序号/限频、NPC 在本地图且距离
     `QUEST_NPC_RANGE_TILES`（3 格）内；事务内再校验任务存在、等级、前置已
     claimed、未接取/未领取。
   - 交付在单事务内：加经验（可升级并回满）、加金币（钱包 + 账本
     `reason='quest_reward'`）、放奖励物品（背包不足整体回滚）、标记 claimed。
     重复 `commandId` 返回 deduplicated，不重复发奖。
5. **客户端只渲染服务端视图。**
   - 加入世界后发送私有 `quest.snapshot`（任务定义解析后的标题/目标/奖励 +
     本角色状态），单条变化时发送 `quest.update`；不进入公开 Room State。
   - 交付或击杀升级会改变其它任务的可接状态（前置已 claimed、等级达标），因此
     这两条路径在提交后重新下发整条 `quest.snapshot`，避免客户端停留在旧的
     locked 状态直到重登。
   - 任务面板/追踪器不自行计算进度或奖励；接取/交付按钮只是意图，距离不足时
     服务端拒绝。
6. **运营契约同步扩展。** `adminContentDraftUpdateSchema` 是手写的 section
   联合类型，新增 section 时必须加分支；这是 EL-022 记录的横切成本，本轮在
   真实发布时暴露并修复。

## 5. 后果

- **正向**：任务链可以在内容工作台编辑、预览差异、随 Release 发布/回滚；进度
  与奖励不会分叉；重复命令与伪造进度都被服务端阻断；主城守卫成为第二个有功能
  的 NPC，回城有明确目的。
- **限制**：v1 只有击杀目标、同一 NPC 接取/交付、无任务日志/放弃、无每日任务、
  无组队共享；奖励物品必须通用，不能按职业发放。
- **经验仍无流水**：交付经验与击杀经验一样只更新 `characters.exp`，沿用
  TD-DATA-11；金币有 `currency_ledger`。
- **内容回滚**：回滚到不含 quests 的 Release 后，新 Room 不再展示任务，但
  `character_quests` 记录保留；再次激活包含该任务的新 Release 时状态继续有效。
  删除仍被引用的 `questId` 不会破坏加载，但该任务在玩家侧消失。
- **未做**：任务完成时全服公告、任务追踪排序/折叠、NPC 头顶感叹号、任务日志
  历史、收集/到达目标、经验流水。这些按 Alpha 0.3 任务系统扩展评估。
