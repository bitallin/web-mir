# ADR-041：怪物归属、自动拾取与争夺掉落

- 状态：Accepted
- 日期：2026-11-27
- 阶段：Alpha 0.3 S3-E（战利品体验）
- 关联：ADR-020（资产事务）、ADR-035（队伍共享击杀经验与掉落）、
  ADR-037（世界首领）、ADR-039（一键导航）

## 1. 背景

当前掉落与拾取有三个体验问题：

1. 每次击杀都要点击地面战利品或“附近掉落”列表，操作重复；自动攻击与一键
   任务已经让战斗自动化，拾取却仍是手动动作。
2. 战利品的归属按“最后一击”决定。组队时最后一击可能不是主要输出者；野外的
   路人补最后一刀也能拿走战利品，缺乏“怪物归属”判定。
3. 点击远处的掉落只会提示距离过远，玩家需要自己先走过去再点一次。

同时，世界首领与未来活动需要一种“无归属、先到先得”的高价值掉落，制造玩家
之间的争夺与 PK 体验。

## 2. 问题

1. **归属权威**：怪物归属、掉落归属、经验/金币/任务进度必须由服务端裁定，
   客户端只能提交攻击与拾取意图。
2. **最后一击不等于贡献**：需要记录“谁先接战/谁在持续输出”，而不是谁补刀。
3. **自动拾取不能绕过资产事务**：物品进入背包仍必须走 `AssetService.pickup`
   的行锁、幂等命令与单事务。
4. **组队共享与自动拾取的冲突**：归属者自动拾取会让队友失去“30 秒内先点
   先得”的窗口；需要明确保留哪一部分。
5. **争夺掉落**：无归属、锁定 60 秒、只能手动拾取，且锁定与解锁必须由服务端
   校验，客户端只显示倒计时。
6. **操作简化**：点击远处掉落应自动走过去，而不是让玩家手动移动后再点。

## 3. 备选方案

1. **继续按最后一击归属**：实现零成本，但补刀抢装备、组队最后一击不等于贡献，
   与“怪物归属”目标冲突。
2. **按最高伤害归属**：需要累计每个玩家/队伍的伤害并在死亡时排序；对治疗、
   拉怪等贡献不友好，且持续伤害与换人场景边界复杂。
3. **先接战归属 + 10 秒无伤害释放（采纳）**：第一次造成伤害的玩家成为归属者；
   之后任何伤害都刷新归属计时，但不会改归属；死亡时经验、金币、掉落与任务
   进度都归归属者；归属者离开地图/死亡超时/怪物重生时释放。最后一击不再
   抢走归属。
4. **客户端自动拾取**：客户端直接把物品拿走会绕过资产事务与服务端权威，
   且无法处理并发拾取与背包已满。
5. **所有人自动拾取**：失去归属与 PK 争夺，争夺掉落无法实现。
6. **归属者自动拾取、队友仅手动共享（采纳）**：归属者在一定范围内自动拾取；
   队友仍可在 30 秒归属窗口内手动拾取（归属者不在范围内时这是唯一的共享
   路径）。争夺掉落永远不自动拾取。

## 4. 决策

### 4.1 怪物归属

- `CombatWorld` 为每个怪物记录 `claimedBy`（角色 id）与 `claimAt`（最近一次
  受击的模拟时间）。
- 第一次造成伤害时设置归属；之后**任何伤害**刷新 `claimAt`，但不改变归属。
  因此放风筝/持续输出不会丢归属，路人补刀也不会抢走。
- 归属超时：20Hz 模拟下 `claimUpdatedAt` 超过 **10 秒**没有伤害，下一次伤害
  重新归属。
- 死亡事件的 `death` 事件带 `ownerId`（归属者）；奖励事务（经验、金币、掉落、
  任务进度）以 `ownerId` 为准，`killerId` 只用于战斗日志与“最后一击”展示。
- 归属者在当前 Room 不存在时不发奖励（奖励不落到离开地图的角色）；离开地图
  时释放其归属，下一次伤害可被其他玩家接战。
- 怪物重生清空归属；不保存到数据库（进程重启后重新接战）。
- 本切片**不阻止**其他玩家攻击已归属怪物，只保证奖励归归属者。攻击锁定可在
  试玩反馈后单独评估。

### 4.2 自动拾取

- 普通掉落保留 30 秒归属窗口；归属者在该窗口内、且存活/在线/未过图、与掉落
  距离小于 `rules.loot.autoPickupRangeTiles`（默认 3 格）时，服务端自动提交
  一次 `AssetService.pickup`。
- 自动拾取复用既有拾取事务：角色行锁、掉落行锁、`loot_pickup` 幂等命令、
  背包容量校验与单事务；不是新的资产路径。
- 自动拾取失败（背包已满）对该掉落退避 5 秒并只提示一次；其他失败退避 2 秒。
- 队友仍可在归属窗口内手动拾取；归属者自动拾取通常会先完成，队友共享因此
  变成“归属者不在附近时”的兜底，而不是主要分配方式（ADR-035 §7 调整）。
- 归属窗口结束后掉落变为自由掉落，不再自动拾取，仍需手动或走近点击。

### 4.3 争夺掉落

- 内容 `lootEntry.contested?: boolean` 标记“无归属、先到先得”的掉落。
- 争夺掉落创建时 `owner_character_id = NULL`、`pickup_locked_until = now +
rules.loot.contestedDelayMs`（默认 60 秒）；过期时间为锁定时间 + 120 秒。
- 锁定期间任何人都不能拾取（服务端返回 `DROP_LOCKED` 与剩余毫秒）；解锁后
  任何玩家都可以手动拾取，永不自动拾取。
- 世界首领的专属掉落（灰烬之心、首领胸甲与三职业 12 级武器）标记为争夺掉落；
  普通药水仍按归属者掉落处理。
- 击杀经验、金币与任务进度仍归归属者；争夺只针对物品，不影响成长奖励。

### 4.4 远处拾取自动走近

- 点击超出拾取距离（1.5 格）的掉落时，客户端向服务端发送既有 `move.to` 到
  掉落所在格，并在到达拾取距离后发送既有 `loot.pickup`；两条命令都由服务端
  校验，不新增协议。
- 手动移动、攻击、死亡、过图或掉落消失都会取消“走近拾取”。
- 锁定中的争夺掉落不自动走近：客户端提示剩余锁定时间。

### 4.5 表现

- `loot.claimed` 到达时，客户端在地面掉落与拾取者之间播放物品图标飞行轨迹；
  本地玩家拾取时额外让背包按钮脉冲一次，表达“已进入背包”。
- 争夺掉落在地面与“附近掉落”列表显示锁定倒计时；解锁后恢复正常拾取样式。

## 5. 后果

- 数据库增加 `world_drops.pickup_locked_until`（可空时间戳），迁移向前兼容；
  怪物归属是内存状态，不持久化。
- 最后一击不再决定奖励；服务端集成测试需覆盖“他人补最后一刀，归属者仍拿
  奖励”，以及归属超时后的重新归属。
- 现有按“击杀者拾取”的集成/E2E 用例需要改为归属者自动拾取或争夺掉落流程。
- 队伍共享掉落的语义从“主要分配方式”调整为“归属者不在附近时的兜底”；
  ADR-035 的相应说明需要更新。
- 内容 Release 新增 `rules.loot` 与首领争夺标记；历史 Release 无这些字段时
  使用代码默认值（自动范围 3 格、争夺锁定 60 秒），checksum 不受影响。
- 未覆盖：归属可见标识、攻击锁定、自动拾取开关、跨进程归属协调、掉落分配
  规则（队长分配/需求贪婪）。
