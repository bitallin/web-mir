# ADR-039：一键任务导航、自动战斗与自动返回

- 状态：Accepted
- 日期：2026-11-27
- 阶段：Alpha 0.3 S3-B（新手引导与任务流程）
- 关联：ADR-016（权威移动）、ADR-034（任务链）、ADR-038（每日任务）、
  ADR-025（服务端自动攻击）、TD-QA-11（共享世界实体的 E2E 隔离）

## 1. 背景

每日任务和主线任务已经能让玩家“有目标”，但完成一次任务的完整操作仍是：
找守卫接取 → 自己走到野外 → 找到目标怪 → 逐只点击 → 走回主城 → 交付。
新玩家容易迷路、找不到目标，也不知道任务完成后该做什么。产品目标是
“点击一次就能看到角色去做，完成后一次点击就能回来交付”。

## 2. 问题

1. **服务端权威不可妥协**：客户端不能瞬移、不能决定最终坐标、不能替服务端
   选目标或结算奖励。
2. **跨地图**：任务发布者在主城，目标怪在野外；导航必须走传送门，并在过图
   后继续。
3. **不能另造战斗链路**：自动战斗必须复用既有的自动攻击（射程、冷却、安全区、
   目标死亡/丢失），否则会出现两套伤害与移动语义。
4. **交付仍是资产事务**：到达守卫后不能由服务器直接发奖；奖励必须走既有的
   `quest.claim` 资产命令、幂等键与行锁。
5. **玩家随时可以接管**：手动移动、手动攻击、停止、死亡都必须立即取消自动化。
6. **可测试**：自动战斗会与其他 E2E 场景争抢共享世界的怪物；测试必须能隔离
   野区实例。

## 3. 备选方案

1. **客户端自动寻路/瞬移**：实现快，但客户端决定位置，违反 ADR-016，也绕过
   地图风险与阻挡；瞬移还会让野外 PvP 与补给决策失去意义。
2. **服务器直接瞬移**：同样破坏风险与世界观；移动速度与路径不可预测。
3. **服务器导航状态机 + 客户端重放意图（采纳）**：服务器计算路线、选目标、
   执行移动与攻击；客户端只提交“前往/返回/停止”的意图，并在过图或重连后
   重放意图。交付仍由客户端在到达后发送既有命令。
4. **服务器代发交付命令**：会让资产命令的来源与幂等键脱离客户端；且到达时
   背包已满等失败需要复杂的回退。保持客户端发起、服务器校验。

## 4. 决策

1. **协议**
   - 客户端 `quest.navigate`：`{ questId, purpose: 'hunt' | 'return' | 'stop' }`，
     带协议版本、commandId、clientSequence，走既有命令守卫（幂等、序号、限频）。
   - 服务器 `quest.navigation`：`{ questId, purpose, status, mapId?, reason? }`；
     `status` 为 `moving | waiting | arrived | stopped | completed`，`reason`
     只在 `stopped` 时出现。
2. **路由（纯函数）**
   - `apps/game-server/src/world/questRouting.ts`：
     `nextPortalToward`（地图图上的最短下一跳）、`nearestSpawnTile`（最近刷点）、
     `findNpcApproachPath`（NPC 周围 3 格内可达且路径最短的落脚点）。
   - 路线只依赖编译地图与 `MAP_MANIFESTS`，可用固定地图做单元测试。
3. **执行（Room tick）**
   - 每个 tick 在自动攻击之前运行 `updateQuestNavigation`；只有当前意图存在时
     才工作，不增加其他玩家的开销。
   - `hunt`：优先选择可见且存活的最近目标，交给既有 `AutoAttackState` 与
     `updateAutoAttacks`；没有可见目标时走向最近刷点并等待刷新。
   - `return`：走到守卫周围的可达格；进入范围后发送 `arrived`，清空路径。
   - 跨图：走向通往目标地图的第一段传送门；踩到传送门由既有传送逻辑处理。
     过图会创建新 Room，服务器静默清除意图，客户端在新 Room 加入后重放。
   - 目标死亡后暂停 400ms 再选下一个，让击杀奖励事务先提交，避免多打一只。
4. **交付**
   - 到达后客户端发送既有 `quest.claim`；服务器仍校验 NPC 距离、任务状态、
     背包与幂等键。自动交付失败（背包满、位置变化）时停止自动化并提示玩家
     从面板手动交付。
5. **取消**
   - 手动移动、手动攻击、停止自动攻击、死亡、过图、断线都会取消导航。
   - 手动移动/攻击/停止是“静默取消”（客户端已知道自己的操作）；死亡与无路线
     会发送 `stopped` 及原因，客户端给出提示。
6. **界面**
   - 任务面板/追踪器提供「接取并前往」「前往击杀」「回去交付」「停止自动」。
   - 顶部/左栏显示自动导航状态（前往、等待刷新、返回、交付中），不覆盖玩家
     与画面中心；进度、完成与交付都有 Toast。
   - 任务视图的守卫名字改为从全部地图解析，野外不再显示 `town_guard` 机器名。
7. **测试隔离**
   - 新增仅开发环境的 `?freshTransfer=1`：过图时为自动化场景创建独立地图实例，
     避免一键战斗抢占其他 E2E 的刷点。生产环境不读取该参数。

## 5. 后果

- **正向**：新玩家一次点击即可完成“接取→前往→战斗→返回→交付”；所有移动与
  目标仍由服务器裁定；复用既有自动攻击与资产事务，没有第二套战斗/发奖路径；
  不新增数据库迁移或内容发布；中断后可以手动接管。
- **成本**：自动战斗只用普通攻击，不会自动放技能；目标选择是“最近的可见怪”，
  可能与其他玩家争夺；导航意图是连接级状态，断线/过图后依赖客户端重放；
  自动交付由客户端在到达后触发，而不是服务器直接发奖；瞬移没有实现。
- **非目标**：瞬间传送、自动使用技能/药品、离线挂机、跨区服导航、自动拾取。

## 6. 验证

- 路由单元：直达/中转传送门、最近刷点、NPC 可达落脚点。
- 契约：三种意图、服务器状态与 `reason` 约束。
- Room 集成：接取每日任务后发送 hunt，收到 `moving` 且下一跳是野外；发送
  stop 后收到 `stopped(manual)`。
- 浏览器 E2E：一键接取并前往 → 自动过图与击杀 5 只史莱姆 → 一键返回 →
  到达守卫后自动交付，金币增加、追踪器清空；完成态显示「守卫」而非 NPC id。
- 全量回归：540 个单元/集成测试、44 个浏览器 E2E（新场景约 47 秒）。

## 7. 补充（2026-11-27）：全局任务面板与远程接取

**背景**：第一版在野外只显示进行中/已完成任务；其他地图上“可接取”的任务被
过滤掉，玩家必须先自己走回发布者才能接取。用户反馈希望在任意地图都能看到
任务清单与状态，并且点一下就能去接取。

**补充决策**

1. 默认任务面板改为**全局清单**：服务器本来就会下发全部任务，客户端不再按
   当前地图过滤；每行显示任务状态与发布者所在地图（如「晨曦主城·守卫」）。
   从 NPC 点开的面板仍只显示该发布者的任务。
2. 新增 `accept` 导航目的：任意地图点击「前往接取」，服务端按传送门图把
   角色送到发布者身边；到达后客户端发送既有 `quest.accept`，接取成功后自动
   开始 `hunt`。接取仍是客户端发起的资产命令，服务器照常校验距离、等级、
   前置与状态。
3. 服务端在开始 `accept` 导航前用任务视图校验状态必须是 `available`；
   其它状态返回 `QUEST_UNAVAILABLE`/`QUEST_ALREADY_CLAIMED`。
4. 仍未实现瞬移：远程接取是“自动走过去”，不是“远程直接接取”或“瞬间移动”；
   旅程与地图风险保留。
5. 任务提示、追踪器与面板都显示发布者地图；发布者名字来自全部编译地图。

**验证**：新增 Room 集成用例（野外对主城任务发起 accept，下一跳为主城）与
浏览器 E2E（野外打开全局面板→「前往接取」→自动回城→自动接取→自动开始
狩猎→停止）；全量 541 测试、45 个 E2E。
