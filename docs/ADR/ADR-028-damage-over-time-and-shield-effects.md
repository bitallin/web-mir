# ADR-028：持续伤害与护盾效果、技能解锁顺序

- 状态：Accepted
- 日期：2026-11-26
- 阶段：Alpha 0.2 S2（任务 2）
- 关联：ADR-011（Effect DSL 白名单）、ADR-019（战斗领域）、ADR-022（内容发布）、
  ADR-027（法力回复）；`docs/ALPHA_02_EXECUTION_PLAN.md` §4、EL-004、EL-017

## 1. 背景

S2 已让法力可以恢复，但三个职业仍只有一个技能，职业差异只体现在数值上。要让
玩家“玩出”职业差别，需要至少三类技能：直接伤害、治疗、持续伤害与减伤。现有
Effect 白名单只有 `directDamage` 与 `heal`，无法表达道士的毒、战士/法师的护盾。

同时发现一个内容存储带来的顺序问题：Content Release 的 payload 存在 PostgreSQL
`jsonb` 中，键顺序会按长度/字节重排；技能栏如果依赖对象顺序，会在不同 Release
间把快捷键 2 的技能排到快捷键 1 前面。

## 2. 决策

### 2.1 新增两种 Effect：`dot` 与 `shield`

```json
{ "kind": "dot", "multiplier": 0.6, "flatDamage": 2, "tickIntervalMs": 1000, "durationMs": 6000 }
{ "kind": "shield", "baseAmount": 40, "amountPerLevel": 6, "durationMs": 8000 }
```

- `dot` 只能以敌方为目标；`shield` 只能以自身为目标（内容校验强制）。
- `dot` 的每跳伤害在施法时确定：
  `max(1, round(attack × multiplier + flatDamage − defense × 0.5))`。
  **不掷命中/暴击，也不消耗 RNG**。固定伤害让回放不受“是否刚好在跳伤时刻施法”
  影响，符合 ADR-019 “RNG 抽取次数固定”的约束。
- `dot` 以技能 ID 为键，重复施放刷新持续时间与伤害，不叠层；目标死亡/重生时清除。
- `shield` 以角色为单位，重复施放替换旧护盾；死亡时清除；到期由 tick 清除。
- 护盾先吸收伤害再扣 HP；吸收后剩余护盾为 0 时立即失效。

### 2.2 事件扩展（加法）

- `hit` 新增可选字段：`skillId`、`absorbed`、`periodic`。`damage` 仍是本次攻击的
  原始伤害，`absorbed` 表示被护盾吃掉的部分，客户端用二者计算实际掉血。
- 新增 `shield` 事件：`{ sourceId, targetId, amount, expiresInMs }`。`amount > 0`
  表示获得/刷新护盾，`amount = 0` 表示耗尽或到期。只投递给施法者与目标（AOI）。
- 旧客户端不认识 `shield` 事件会忽略；未知字段不影响解析（`.strict()` 只在
  服务端写入时生效）。

### 2.3 技能按解锁等级排序

`skillsForClass` 不再依赖内容对象的键顺序，而是按 `levelRequirement`、再按
`hotkey` 排序后返回。原因：`jsonb` 会重排对象键，直接使用对象顺序会让技能栏
顺序随 Release 变化；排序后客户端第 1/2/3 个按钮稳定对应快捷键 1/2/3。

### 2.4 内容基线

每职业 3 个技能，1/5/10 级解锁：

| 职业 | 1 级           | 5 级               | 10 级            |
| ---- | -------------- | ------------------ | ---------------- |
| 战士 | 重击（伤害）   | 铁布衫（护盾）     | 破军斩（伤害）   |
| 法师 | 火球术（伤害） | 魔法盾（护盾）     | 陨石术（伤害）   |
| 道士 | 治愈术（治疗） | 施毒术（持续伤害） | 灵魂火符（伤害） |

## 3. 备选方案

| 方案                        | 未采用原因                                      |
| --------------------------- | ----------------------------------------------- |
| DoT 每跳走完整命中/暴击判定 | 消耗 RNG、跳伤可能全空，手感与回放都更难解释    |
| DoT 叠层                    | 需要层数上限与新的 UI，首版收益低               |
| 护盾做成百分比减伤          | 与防御属性叠加难解释，且无法表达“吸收量”        |
| 新增独立 Buff 状态同步协议  | 首版只有护盾一种持续增益，事件 + 客户端计时足够 |
| 用客户端计时驱动跳伤        | 违反服务端权威；断线与加速会破坏公平            |
| 依赖内容对象顺序渲染技能栏  | `jsonb` 不保证顺序，已在 E2E 中实际复现顺序错乱 |

## 4. 影响

- 正面：三职业在 5/10 级获得可感知的新操作；道士有持续伤害、战士/法师有减伤；
  技能栏顺序稳定；服务端权威与确定性回放保持。
- 限制：DoT 不会暴击、不受命中影响；护盾不区分伤害类型；状态不持久化到数据库，
  重连后服务端仍保留护盾，但客户端事件状态会重置（下一次受伤/施法重新同步）。
- 风险：护盾与治疗叠加可能拉长战斗；通过 MP 成本、冷却与后续怪物压力调节。
- 兼容：旧 Release 没有 `dot`/`shield` 技能，行为不变；新 Release 需要发布并
  激活后才对新 Room 生效。

## 5. 验收

- 领域：DoT 每秒一跳、持续 6 秒后停止、击杀归属施法者；DoT 不改变后续攻击的
  RNG 结果；护盾先吸收伤害、到期清除；4 级不能使用 5 级技能。
- 内容校验：`dot` 只能敌方、`shield` 只能自身；持续时长不能短于一个跳伤间隔。
- 服务端集成：5 级 profile 返回两个技能；毒伤跳伤与击杀通过 `combat.event`
  广播；护盾吸收怪物伤害且 HP 不变。
- 浏览器 E2E：道士 5 级施毒看到持续伤害并击杀；战士 5 级开盾看到护盾吸收。
