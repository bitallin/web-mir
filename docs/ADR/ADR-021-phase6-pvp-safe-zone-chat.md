# ADR-021: 阶段 6 服务端 PvP、安全区与聊天治理

- 状态：Accepted
- 日期：2026-11-25
- 关联：MVP 计划阶段 6、架构文档 8.3–8.7 / 9.2 / 11.3 / 14.2、ADR-004、ADR-008、ADR-018、ADR-019、ADR-020

## 背景

阶段 1–5 已经交付服务端移动、地图实例/AOI、怪物战斗与事务化资产，但战斗目标
只有怪物，主城与野外没有 PvP 规则；玩家死亡只存在内部计时，没有对外倒计时；
聊天只有限频与长度限制，没有内容过滤与系统消息。阶段 6 要求形成“主城安全区、
野外基础 PK、死亡与复活、同图聊天治理、玩家 HUD 完善”的多人互动闭环，同时
必须满足：

- 客户端只提交意图，伤害、死亡、复活和区域规则全部由服务端判定；
- 客户端不能通过伪造地图、坐标或区域绕过安全区；
- 固定 tick 不等待 IO，聊天与战斗命令仍在既有命令管线内；
- 私有数据不进入公开状态，系统消息不能泄露账号或背包信息；
- 新规则必须可配置、可测试、可回放，不能写死在 Room 分支里。

## 决策

1. **安全区写入编译地图。** `MapRuntimeManifest` 增加 `pvpMode: 'none' | 'open'`，
   `MAP_RUNTIME_SCHEMA_VERSION` 升到 `2`。编译期按 Tiled 的 `kind` 生成：
   `town → none`、`wilds → open`，并纳入 checksum。服务端 Room 只读取自己固定的
   编译产物；客户端提交的 mapId、坐标、房间名都不能改变该规则。客户端小地图
   与 HUD 从同一产物显示状态，但只作为展示。
2. **玩家目标进入 CombatWorld。** 普攻与伤害技能接受 `targetId` 为玩家或怪物；
   `CombatWorld` 位于 `game-domain`，不依赖网络或数据库。玩家目标校验顺序为：
   目标存在 → 地图允许 PvP（否则 `SAFE_ZONE`）→ 不能攻击自己 → 目标存活 →
   目标可被选中（断线宽限期不可选）→ 攻击间隔 → 距离。安全区拒绝先于冷却与
   距离，避免主城点击返回令人困惑的冷却错误。
3. **PvP 复用同一套结算公式。** 命中、暴击、浮动与防御减伤继续使用
   `rollAttack`；玩家目标使用其装备后 `CombatStats.defense`。服务端 RNG 与
   固定抽取次数不变，因此 PvP 与 PvE 都能用固定种子回放。PvP 击杀不产生经验、
   金币或掉落，也不做红名、爆装、罪恶值或死亡惩罚——这是 MVP 明确排除项。
4. **死亡与复活。** 玩家死亡事件增加可选 `reviveInMs`，服务端在
   `playerRespawnMs`（默认 3 秒）后把角色传送到地图编译出生点、回满 HP/MP 并
   广播 `respawn`。客户端据此显示复活倒计时与“已复活”反馈；倒计时只是表现，
   复活时刻与位置由服务端决定。断线玩家仍按计时复活，重连后从状态恢复。
5. **聊天过滤是纯函数。** `game-domain` 新增 `ChatFilter`：
   - 先做 NFKC 归一用于匹配，防止全角/兼容字符绕过；广播保留玩家原始标点；
   - 内置规则拦截链接/网址、交易引流、8 个以上重复字符刷屏；
   - 规则集合可注入，Room 默认使用内置规则，测试可注入单条规则；
   - 被拦截消息不广播、不进入最近消息窗口，只给发送者一条 `system.notice`
     警告并计入 `chatFiltered` 指标。
     既有长度上限、控制字符拒绝、4/2s 令牌桶与消息幂等保持不变。
6. **系统消息使用公开 `system.notice`。** 加入/离开地图、PvP 或 PvE 死亡、
   升级、聊天拦截都广播或定向发送 `system.notice`；只包含显示名、地图名与
   公开战斗结果，不包含账号、背包、金币流水或管理员信息。客户端把系统消息
   与地图聊天分开展示，但同处聊天面板。
7. **协议增量。** 新增拒绝码 `SAFE_ZONE`、`CHAT_BLOCKED`；`combat.profile`
   增加 `pvpEnabled` 与 `reviveMs`；`death` 事件增加可选 `reviveInMs`。
   保持 `PROTOCOL_VERSION = 1`：字段均为增量，旧客户端只是看不到新状态。
8. **客户端体验。** 玩家可以点击其他玩家或在玩家列表发起攻击；目标面板同时
   支持怪物与玩家；角色头顶增加等级与 HP 条；新增按地图编译产物绘制的小地图、
   角色面板（`C`）、安全区/野外标识、复活倒计时、断线/重连覆盖层与音效开关。
   音效暂用 WebAudio 合成占位音，不依赖未交付的音频资源；正式音效与美术在
   阶段 8 的资源门禁中替换。

## 理由

- 把 PvP 规则编译进地图，使“安全区”与地图内容同版本、同 checksum，Room 无需
  读取客户端字段或可变的运行期开关，最容易证明不可伪造。
- 玩家与怪物共用战斗函数，减少两套伤害公式漂移的风险，也让测试回放覆盖 PvP。
- 死亡倒计时放在事件而不是公开状态中：它只对当事人有意义，且状态字段越少，
  AOI patch 成本越低。
- 聊天过滤放在纯领域函数而不是 Room 内联正则，便于单测、注入替换和后续接入
  审核服务；Room 只负责身份、限频和发送。
- 系统消息与聊天分开建模，避免把系统文本伪装成玩家消息（伪造 playerId），
  也不给客户端提供任何“系统账号”的信任入口。

## 影响

- `content/maps/compiled/*.json` 重新生成：schema 2、`pvpMode`、新 checksum。
- `game-domain` 增加玩家目标战斗、`ChatFilter` 与相关测试；`CombatWorldOptions`
  增加 `pvpEnabled`。
- `game-server` 读取地图 PvP 规则，新增系统消息、聊天过滤、`chatFiltered` /
  `pvpKills` 指标；Room 仍不包含战斗公式。
- `game-web` 增加玩家目标、玩家 HP 条、小地图、角色面板、复活倒计时、连接
  覆盖层与合成音效；`WorldSceneHandle.selectMonster` 改为 `selectEntity`。
- 已知限制：只按整张地图划分安全区，不支持野外局部安全区；PvP 没有红名、
  击杀公告可选开关或战报持久化；聊天过滤是静态规则，不含人工审核与词库热更新；
  合成音效是占位，不代表最终音效设计。
