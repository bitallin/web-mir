# ADR-044：队伍管理、队伍聊天与跨图投递

- 状态：Accepted
- 日期：2026-11-27
- 阶段：Alpha 0.3 S4-A 队伍社交切片
- 关联：ADR-035（组队与共享经验/掉落）、ADR-036（进程级 PartyService）、
  TD-CLI-17、路线图 4.3“组队与社交”、架构文档 7.4（聊天）

## 1. 背景

ADR-035/036 交付了邀请、接受、离开、跨图保留的名单与共享奖励，但队伍 UI 只有
名单与「离队」（TD-CLI-17）：没有队伍聊天、队长移交、踢人。组队因此只解决了
“在一起打”，没有解决“一起协调”。

路线图把“队伍聊天、队长转移”列为 Alpha 0.3 的社交目标；本轮用户要求继续推进
项目，执行计划把队伍社交列为下一片。地图内的到达目标标记（TD-CLI-24）是独立的
表现层补强，不在本 ADR 范围。

## 2. 问题

1. **权限**：移交与踢人只能由队长执行；权限必须在服务端判定，隐藏 UI 不算权限。
2. **被踢者的状态**：被踢者仍在世界中，必须保留世界会话与在线状态，只清空队伍
   名单；不能把“踢出队伍”实现成断线。
3. **跨图投递**：队伍可以跨图（ADR-036）。队伍聊天不能只广播给当前地图 Room，
   否则过图的队友收不到。
4. **协议复用**：地图聊天已有过滤、限频、禁言、去重与指标。队伍聊天不应复制一
   套并行协议，也不应把私密消息广播给同图陌生人再由客户端过滤。
5. **兼容性**：服务端与浏览器同时发布，但聊天消息的 `channel` 原本固定为
   `'map'`；扩展必须保持旧客户端省略字段时仍按地图频道工作。
6. **房间边界**：Room 只做适配（AGENTS §2.6）。成员与权限规则应留在进程级
   `PartyService`/`PartyRegistry`，Room 只做命令解析、门禁与消息路由。

## 3. 备选方案

1. **独立的 `party.chat` / `party.message` 消息**：客户端要维护两条日志，过滤、
   限频、禁言、去重与指标全部复制；拒绝。
2. **队伍聊天仍走 Room 广播，客户端按频道过滤**：私密消息会到达同图所有客户端，
   等于把队伍内容泄露给陌生人；拒绝。
3. **踢人即断开连接**：把社交操作当成惩罚会话，丢失世界状态并绕过队伍语义；
   拒绝。
4. **在 Room 内校验队长身份、直接改名单**：Room 会持有队伍规则，且跨图队友的
   名单刷新需要额外广播；拒绝。
5. **在 `PartyRegistry` 判定权限、`PartyService` 按成员所在 Room 投递，
   `chat.send` 增加可选频道（采纳）**。

## 4. 决策

### 4.1 队长移交与踢人

- 新命令 `party.transfer` 与 `party.kick`，均带 `targetPlayerId`，复用现有队伍
  命令门禁：协议版本、`commandId` 去重、客户端序号、限频。命令只改内存状态，
  同步执行，不进入资产队列。
- 权限在 `PartyRegistry` 内判定：必须是队伍成员且是当前队长；目标必须是同队
  成员、且不能是自己。拒绝原因映射为 `PARTY_NOT_IN_PARTY`、`PARTY_NOT_LEADER`、
  `PARTY_TARGET_NOT_MEMBER`、`PARTY_TARGET_SELF`。
- 移交只改 `leaderId`，队伍与成员顺序不变；成功后向所有成员刷新名单并发送系统
  提示。
- 踢人移除成员、丢弃该成员发出与收到的邀请；队长不能被踢，所以队伍至少保留
  队长一人。被踢者的世界在线状态与 presence 保留，只清空队伍归属。
- 被踢者可能在其他地图：`PartyService.kick` 用 presence 路由刷新，而不是只刷新
  “剩余成员”。这与 `refreshMembers` 的机制一致，Room 的刷新实现根据当前名单
  生成快照；对非成员自然生成 `party: null`。

### 4.2 队伍聊天

- 复用 `chat.send` / `chat.message`，新增 `channel: 'map' | 'party'`。`chat.send`
  省略频道时默认 `map`，旧客户端行为不变；`chat.message` 的频道改为同一枚举。
- 服务端在 `handleChat` 中解析频道；`party` 频道要求发送者在队伍中，否则返回
  `PARTY_NOT_IN_PARTY`。过滤、禁言、限频与 `clientMessageId` 去重与地图聊天
  完全相同；一次消息只计一次指标。
- 地图频道保持 Room 广播；队伍频道通过 `PartyService.deliverChat` 逐个成员投递，
  由成员当前所在 Room 的端口发送。消息不进入公开 Room State，也不广播给非成员。
- 正在过图、暂时没有 Room 的成员会漏掉这条消息（与名单显示“断线”一致）；没有
  离线消息队列。

### 4.3 客户端

- 聊天面板提供「附近 / 队伍」频道切换；不在队伍时队伍频道禁用，离开或被踢后
  自动回到附近频道。队伍消息带「队伍」标签。
- 队长在队伍面板看到每个成员的「移交」「踢出」操作；非队长不渲染这些按钮。
- 所有操作仍然只是意图；客户端不修改名单或队长状态。

### 4.4 兼容性与持久化

- 协议版本不变：`channel` 是可选/默认字段，旧客户端继续使用地图聊天。
- 无需数据库迁移：队伍仍是进程内状态（TD-SRV-11 不变）。
- 无内容发布：不新增内容字段或数值。

## 5. 后果

- 组队可以协调与自我管理；被踢/移交后服务端会立即纠正双方 UI。
- 队伍仍是单进程状态：重启丢失、多进程不可共享（TD-SRV-11）；队伍聊天同样
  受此限制。
- 没有离线消息、聊天历史或频道持久化；不在本切片。
- 按名字邀请、世界/公会频道仍属后续工作（TD-CLI-17 仅部分关闭）。
- 被踢者只看到名单消失，没有单独的“你已被移出队伍”提示；服务端已有系统提示
  给剩余成员。若试玩需要，可在后续切片补充跨 Room 的定向提示。
