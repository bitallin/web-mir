# ADR-043：八方向移动与键盘操作

- 状态：Accepted
- 日期：2026-11-27
- 阶段：Alpha 0.3 移动切片
- 关联：ADR-016（服务端权威移动）、ADR-017（会话票据）、架构文档 3.1 / 7.2 / 8.2

## 1. 背景

ADR-016 冻结的移动模型是四方向网格：BFS 只走 N/E/S/W，斜向目标需要 L 形路线，
客户端预测与转弯也按轴对齐处理。试玩反馈与路线图都把“键盘八方向短步与停止”
列为待补的辅助操作；技术债 TD-CLI-07（无键盘移动、无停止指令）与 TD-CLI-18
（四方向、斜向走 L 线）一直没有关闭。ADR-016 明确要求：如果确认斜向移动更符合
手感，应单独评估八方向、斜向阻挡规则与预测改造，并更新 ADR，而不是在寻路实现里
局部放宽。

本轮用户明确要求“八方向操作，目前是四方向”，因此按 ADR-016 预留的路径实施。

## 2. 问题

1. **斜向阻挡**：允许对角步后，角色能否从 (0,0) 直接走到 (1,1)，即使 (1,0) 或
   (0,1) 是墙？允许就会“切角”穿墙，破坏碰撞直觉。
2. **速度**：对角步的直线距离是 √2 格；若仍按 1 格耗时，斜向移动会比直线快约
   41%，形成走位优势。
3. **预测一致性**：客户端与服务端必须用同一套路径与转向规则，否则每帧预测会
   被快照反复拉回。
4. **朝向**：逻辑朝向只有四个值；斜向移动时角色应面朝哪里，且不能破坏已持久化
   的 `characters.facing` 数据。
5. **重寻路回退**：ADR-016 的补充规则为保持轴对齐会在格内先回中心；八方向后
   是否还需要这个回退？
6. **停止语义**：手动移动只有 `move.to`；点击当前格虽然能得到空路径，但客户端
   预测位置通常领先服务端一格，用客户端坐标发停止会多走一段。需要明确的停止
   指令。
7. **键盘输入**：按住方向键连续走、两键组合斜走、停止键，且不能与聊天/输入框
   和技能快捷键冲突。

## 3. 备选方案

1. **保持四方向，只加键盘四方向键**：改动最小，但没有解决斜向观感，也无法关闭
   TD-CLI-18。
2. **八方向但只允许“无障碍对角”之外的 4 方向寻路，客户端自行斜插**：客户端会
   与服务端路径不一致，违反服务端权威。
3. **对角步允许切角**：实现简单，但角色会穿墙角，是明显的碰撞缺陷。
4. **浮点坐标与任意角度移动**：与现有整数子格模型、确定性回放和持久化冲突。
5. **新增 `move.stop` 命令（采纳）**：显式停止，语义清楚，可复用统一命令门禁。
6. **八方向 BFS + 斜向阻挡 + 欧氏速度 + 客户端同规则预测（采纳）**。

## 4. 决策

### 4.1 寻路与阻挡

- `findPath` 使用八邻域 BFS，步数代价相同；邻居顺序固定（自北顺时针），并在
  展开时按到目标的欧氏距离排序，使同长度路径优先走直线而不是“绕一行”。
- **斜向步只在两个正交相邻格都可走时合法**：从 `(x, y)` 到 `(x+dx, y+dy)` 要求
  `(x+dx, y)` 与 `(x, y+dy)` 都可走。这样路径永远不会切过被阻挡的墙角。
- `game-simulation` 导出 `isStepAllowed`；`WorldSimulation.setPath` 校验相邻性
  与斜向阻挡，非寻路来源的路径也不能注入非法对角步。
- `game-domain` 的测试用 BFS（`testSupport.bfsPath`）同步为八方向，保持注入
  路径与生产寻路一致。

### 4.2 速度与位置

- 每段行进距离使用欧氏长度 `round(hypot(dx, dy))`；对角步约 1414 单位，
  按 4000 单位/秒走约 353ms，与直线步的 250ms 成 √2 比例相同，**斜向不快于
  直线**。
- 位置仍是整数子格单位。单步预算不足一段时，按 `dx * remaining / distance`
  取整推进两个轴，服务端确定性、可回放。
- 怪物在 `CombatWorld.advanceMonster` 使用同一规则，避免怪物斜向加速。

### 4.3 重寻路连续性

- 取消“格内先回中心”的轴对齐回退。新路径直接从当前位置走向第一个格中心；
  八方向模型下该线段只会经过当前格、目标格及两个正交邻格，而它们已由斜向
  阻挡规则保证可走。
- 客户端 `buildPredictionWaypoints` 与服务端 `setPath` 同步简化：丢弃服务器
  起步格后直接以格中心为路点；空路径表示停止，仍先走回当前格中心。

### 4.4 朝向

- `FACING` 在前四个值（n=0/e=1/s=2/w=3）之后追加四个对角值：
  `northEast=4`、`southEast=5`、`southWest=6`、`northWest=7`。旧持久化数据与
  旧客户端读取 0–3 不受影响；`characterViewSchema` 与 Game Server 的视图校验
  上限改为 7。
- 新增 `facingFromDelta` 纯函数：两轴都有位移时返回对角朝向，否则返回基本
  方向。客户端四方向贴图在表现层用 `facing % 4` 映射（NE→N、SE→E、SW→S、
  NW→W），不要求美术资源扩容。

### 4.5 键盘操作与停止

- WorldScene 直接监听 `WASD` 与方向键；按住时每走完一格（客户端预测路径耗尽）
  再提交下一格 `move.to`，两键组合即斜向，相反键抵消。所有输入仍是意图，
  路径、阻挡与最终位置由服务端裁定。
- 输入框、文本域、下拉框聚焦时忽略；`Ctrl/Meta/Alt` 组合不拦截。
- **新增 `move.stop` 命令**（`protocolVersion` + `commandId` + `clientSequence`）：
  Game Server 经过统一的协议/重复/序号/限频门禁后清空权威路径、停止自动攻击与
  任务导航，返回空路径的 `command.ack`。空格键在客户端发送该命令并清空本地
  预测。
- `Esc` 仍只停止自动攻击；空格是“停止移动 + 攻击”。

## 5. 影响

- 协议为**加法变更**：新命令 `move.stop`；`facing` 取值范围扩大到 0–7。无数据库
  迁移。
- 同长度路径的格数不变或更少；斜向目标不再需要 L 形路线。跳跃/传送与现有
  `move.to` 语义不变。
- 斜向步受“两侧可走”限制：狭窄单格走廊的拐角仍需先走一个正交步，这是有意的
  碰撞规则，不是寻路失败。
- 自动攻击、任务导航、传送门寻路都复用 `findPath`，自动获得八方向路径。
- 风险：四方向贴图无法表现真正的斜向帧，当前用最近基本方向映射；正式美术阶段
  可增加八方向资源，无需再改协议。

## 6. 验证

- 单元：八方向 BFS（直线、对角、绕墙、拒绝切角、确定性）、`isStepAllowed`、
  欧氏步进与斜向朝向、客户端预测对角路径、键盘方向合成与斜向阻挡。
- 集成：真实 Game Server 接受对角 `move.to` 路径并在两轴到达；`move.stop`
  清空路径后位置不再变化。
- 浏览器 E2E：按住 D+S 斜向移动、空格停止后位置稳定；既有移动/自动攻击用例
  不回退。
