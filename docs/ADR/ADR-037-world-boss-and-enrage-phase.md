# ADR-037：世界首领、二阶段狂暴与地图公告

- 状态：Accepted
- 日期：2026-11-27
- 阶段：Alpha 0.3 S2（多人目标与首领）
- 关联：ADR-008（固定 Room 内容版本）、ADR-019（战斗领域与怪物运行时）、
  ADR-030（攻击前摇与扑击预警）、ADR-035（组队共享击杀经验与掉落）、
  ADR-036（进程级队伍）、TD-SRV-11（跨进程状态）

## 1. 背景

Alpha 0.3 S1 交付组队后，10 级以上玩家仍缺少一个“值得一起去打”的目标：
任务链止于白狼王，野外最强怪物是 900 HP 的废墟石像鬼，单人可以稳定击杀。
路线图 Alpha 0.3 的第 2 项是“1 个野外精英 Boss（多人争夺）”。本 ADR 交付
一个内容驱动、服务端权威、可独立验收的世界首领，以及它的二阶段战斗。

## 2. 问题

1. **Boss 不能只是血更厚的怪**：需要读得懂的战斗节奏、多人参与的理由和失败
   风险，否则只是数值堆叠。
2. **阶段行为必须可调但不可执行任意脚本**：项目禁止后台脚本（ADR-011），
   新增行为必须走代码发布；但数值（阈值、倍率）应能由内容调整。
3. **公告与状态归属**：首领狂暴/被击败/重新苏醒是地图级事件，但战斗事件只
   投递给 AOI 内的玩家；两者不能混用。
4. **战利品与经验**：必须复用既有击杀奖励事务、幂等引用、归属窗口与组队共享，
   不能为 Boss 另造一条发奖链路。
5. **协议与状态兼容**：既有 Release 不含新字段；客户端与服务器同批发布，但
   历史内容（无 Boss）必须行为不变。
6. **多进程边界**：Boss 刷新计时器天然属于它所在的地图 Room；多进程/多实例
   需要共享协调，当前单进程不需要。

## 3. 备选方案

1. **代码里硬编码 Boss 与阶段**：实现快，但违反“内容与代码分离”，每次调数值
   都要发版，运营不可见。
2. **通用脚本化 Boss AI（阶段 DSL）**：表达力强，但会变成脚本引擎，违反
   ADR-011 的封闭白名单原则，且当前只有一个 Boss，属于过早抽象。
3. **封闭的内容阶段对象（采纳）**：内容只描述“何时进入阶段、各属性乘以多少”，
   执行仍由领域代码完成；新增行为类型才需要代码发布。

## 4. 决策

1. **Boss 是一个内容标记。**
   - 怪物新增可选 `boss: true`。它只驱动表现与公告（首领血条、金色名字、
     小地图标记、地图公告），不改变战斗数值。
   - 可选字段缺失时保持历史 Release 的 canonical checksum（EL-004）。
2. **狂暴是单次、确定性的内容阶段。**
   - 怪物新增可选 `enrage` 对象：`atHpPermille`（阈值）、
     `attackMultiplier`、`attackIntervalMultiplier`、`moveSpeedMultiplier`、
     `windupRadiusTiles`（前摇半径绝对值）。
   - 每次生命最多触发一次：伤害后 HP 首次 ≤ 阈值且仍 > 0 时进入阶段；致死一击
     不触发。重生时重置。
   - 缺失的倍率表示“不变”；攻击间隔下限 100ms；前摇半径扩大要求怪物本身有
     攻击前摇，否则内容校验报错。
   - 有效属性由纯函数 `monsterStatsAtPhase` 计算，领域测试可直接断言。
3. **阶段切换是战斗事件，公告是地图事件。**
   - 新增 `enrage` 战斗事件（实体、HP、最大 HP），只发给能看到该 Boss 的玩家；
     客户端据此刷新首领血条与战斗日志。
   - 地图 Room 在收到 Boss 狂暴、Boss 死亡、Boss 重生时广播系统公告。公告由
     服务端内容判断（`boss` 标记），客户端不能伪造。
   - 公开状态 `MonsterState` 增加 `boss` 与 `enraged`（默认 false）；怪物位置、
     HP 本来就是公开 AOI 数据，不新增隐私面。
4. **战利品复用既有事务。**
   - Boss 使用普通掉落表：固定掉落材料 + 概率稀有装备；经验/金币仍由
     `grantKillReward` 在同一事务中发放，归属窗口内同队可拾取（ADR-035）。
   - 不为 Boss 新增分配规则、保底共享或全队独立掉落。
5. **客户端呈现。**
   - 顶部边缘的首领血条（名字、等级、HP、狂暴标记），不遮挡玩家与画面中心；
     视野内存在 Boss 时出现，Boss 死亡或离开视野后消失。
   - Boss 体型放大、金/红色名字、狂暴光环；小地图 Boss 为更大的金色/橙色点。
6. **不做的事。**
   - 不做副本实例、多阶段脚本、按阶段更换技能、全服唯一 Boss 状态。
   - 不做 Boss 击杀的额外货币、排行榜或首杀记录。
   - 不做跨进程 Boss 刷新协调；当前每个地图 Room 独立计时。

## 5. 后果

正面：

- 10 级以上玩家有了需要组队、有读条与狂暴压力、且有独占掉落的共同目标；
  内容调整只需发布新 Release，不需要改代码。
- 阶段执行在领域层，可被种子回放与单元测试精确验证；事件与公告分层投递，
  不泄露无关战斗。
- 复用既有资产事务与组队规则，没有新的经济/事务面。

代价与风险：

- `enrage` 是新增协议事件；旧客户端遇到未知事件会解析失败，因此服务端与
  客户端必须同批发布（当前为单一部署单元）。
- Boss 刷新计时器是 Room 进程内状态：进程重启后计时重置，多进程部署时每个
  进程会有自己的 Boss。与 TD-SRV-11 同类，规模化前需要共享协调。
- `atHpPermille` 只有一个触发点；未来需要“多阶段”或“阶段技能”时再扩展为
  数组或新的封闭行为类型，而不是复用本字段。

## 6. 验证

- 领域：阶段倍率、单次触发、致死一击不触发、重生重置、无阶段怪物不变。
- 内容：Boss 定义与狂暴字段、废墟刷点、掉落表、非法前摇半径报错。
- 服务端集成：真实 Room + PostgreSQL，三名角色击败废墟首领，断言狂暴事件、
  地图公告、死亡、固定材料掉落与 900 经验提交。
- 浏览器：真实 Chromium 在废墟看到首领血条与首领标记；截图证据。
- 容量：50 人 × 2 分钟 sanity，tick 与资产失败率不退化。
