## S2 验收（已完成）

1. 内容：Boss 定义、狂暴阶段、独占掉落与地图刷点全部走内容发布，历史 Release
   不受影响。
2. 服务端：阶段切换、有效属性、地图公告与掉落/经验全部服务端裁定；真实
   PostgreSQL + Room 集成测试覆盖三人击杀。
3. 客户端：真实 Chromium 能看到首领血条、首领标记与狂暴状态；首领血条不遮挡
   玩家与画面中心。
4. 容量与资产：50 人 × 2 分钟 sanity 无退化，资产不变量 7/7 为 0。
5. 文档：ADR-037、切片报告、状态、日志、债务与演进记录同步。

## S3-A 验收（已完成）

1. 内容：日常任务、重置规则与两个日常全部走内容发布；旧 Release 与一次性
   任务行为不变。
2. 服务端：重置边界是注入时钟的纯函数；接取/交付/击杀推进按周期键隔离；
   在线玩家跨过重置点会收到新快照与公告。
3. 客户端：真实 Chromium 能看到「日常」标签、重置时刻与「今日已完成」；
   追踪器正确显示 0/5 与交付后的清空。
4. 测试：11 条新增单元/集成与扩展的真实 E2E 覆盖同日重复、跨日重接与奖励唯一。
5. 容量与资产：50 人 × 2 分钟 tick p95 5.11ms、0 资产失败；不变量 7/7 为 0。
6. 文档：ADR-038、切片报告、状态、日志、债务与经验记录同步。

## S3-B 验收（已完成）

1. 服务端：一键前往/返回是服务端导航状态机；路线、目标选择、移动与到达
   全部由服务器裁定，客户端只提交意图。
2. 跨图：从主城到野外走传送门；过图后客户端重放意图，自动继续。
3. 战斗：复用既有自动攻击（射程/冷却/安全区/目标死亡），不新增伤害链路。
4. 交付：到达守卫后客户端发送既有 `quest.claim`；奖励事务、幂等与距离校验
   不变；自动交付失败回退到面板。
5. 客户端：接取并前往、回去交付、停止自动、状态横幅与进度/完成/交付提示；
   不遮挡玩家与画面中心。
6. 验证：540 测试、44 个浏览器 E2E（串行全量 44/44）、资产不变量 7/7 为 0。

## S3-C 选择依据（下一轮）

按“价值 / 依赖 / 风险”排序：

1. **10 步主线任务链**：直接延续 S3-A/S3-B 的目标链，依赖既有任务 section、
   周期机制与一键流程，不需要新架构；风险在任务数值与内容量。
2. **日常目标类型扩展（collect/对话/到达）**：让日常与主线的玩法更丰富，
   但需要新的进度事件与物品扣除规则，工作量中等。
3. **3 人副本实例**：多人价值最高，但需要动态 Room/实例路由 ADR、进入条件、
   复活与掉落分配；工作量明显大于一个切片。
4. **交易/排行榜**：经济与审计面大，应在内容量与留存验证后再做。

除非试玩给出相反信号，S3-C 优先 10 步主线；副本实例先写 ADR 再实施。

  过图/断线后依赖客户端重放；Room 编排继续增长（TD-SRV-01b）。
- 保持：TD-SRV-11（队伍仅内存）、TD-CLI-17（队伍聊天/分配/移交）、
  TD-CLI-13（正式美术）。
- S2 不新增数据库迁移、不改资产模型、不引入 Redis；S3-A 增加一条向前兼容

  无内容发布。
