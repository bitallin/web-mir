# Alpha 0.3 执行计划：多人目标与社交

> 版本目标与范围以 `docs/PROJECT_ROADMAP.md` 第 4 节为准；本文件只记录当前
> 版本内的切片顺序、验收与债务影响。每完成一个切片更新本文件与
> `docs/PROJECT_STATUS.md`。

- 主题：回答“玩家为什么每天回来”——目标链、组队合作、玩家间竞争。
- 原则：每两周一个可独立验收的纵向切片；不做大爆炸发布；经济与资产改动必须
  事务化 + 账本 + 审计。

## S3-B 验收（已完成）

1. 服务端：一键前往/返回是服务端导航状态机；路线、目标选择、移动与到达
   全部由服务器裁定，客户端只提交意图。
2. 跨图：从主城到野外走传送门；过图后客户端重放意图，自动继续。
3. 战斗：复用既有自动攻击（射程/冷却/安全区/目标死亡），不新增伤害链路。
4. 交付：到达守卫后客户端发送既有 `quest.claim`；奖励事务、幂等与距离校验
   不变；自动交付失败回退到面板。
5. 客户端：接取并前往、回去交付、停止自动、状态横幅与进度/完成/交付提示；
   不遮挡玩家与画面中心。
6. 全局面板：任意地图打开「任务 · 全部地图」可看到所有任务的状态与发布者
   地点；从 NPC 点开时只显示该发布者。
7. 远程接取：任意地图点「前往接取」，服务端自动把角色送到发布者身边并接取，
   接取成功后自动开始狩猎；接取仍是客户端发起的既有命令，服务器校验距离与
   状态；未实现瞬移。
8. 验证：541 测试、45 个浏览器 E2E（串行全量）、资产不变量 7/7 为 0。

## S3-D1 验收（已完成）

1. 内容：新增收集目标 schema（闭集分支）与两条任务——一次性教学任务
   「巡路补给」（初始药水）与每日「蛛腿征募」（材料消耗）；旧 Release 的
   击杀任务不受影响。
2. 服务端：收集进度从背包汇总派生，拾取不写任务进度；交付在行锁内扣除物品、
   标记完成/已领取并发放奖励，同一事务；数量不足返回 `QUEST_ITEMS_MISSING`
   并整体回滚。
3. 导航：收集任务的「前往击杀」指向掉落该物品的怪物；背包凑够后自动停止；
   「回去交付」把已够数的活动任务视为完成。
4. 校验：目标物品必须存在且为材料/消耗品；每日不能要商店可购买的物品；
   目标物品不能同时是奖励；无来源时告警。
5. 测试：领域视图（进度/完成/领取）、真实 PostgreSQL 交付与多堆叠扣除、
   数量不足回滚、服务端背包变化刷新快照、真实浏览器接取→交付→物品减少。
6. 发布与实测：`2026.11.27.5` 已激活；8584 真实 Chromium 看到两条收集任务；
   50 人 × 2 分钟 sanity p95 5.25ms、0 资产失败；资产不变量 7/7 为 0。
7. 文档：ADR-040、切片报告、状态、日志与债务同步。

## S3-E 验收（已完成）

1. 归属：首次接战者持有怪物归属，最后一击不再抢走经验、金币、掉落与任务
   进度；归属超时、离开地图与重生都会释放。
2. 自动拾取：归属者在内容范围（默认 3 格）内的普通掉落通过既有拾取事务自动
   进入背包；客户端播放物品飞行与背包脉冲；背包已满退避并提示。
3. 争夺掉落：内容标记的条目无归属、锁定 60 秒、只能手动拾取；锁定期间服务端
   返回 `DROP_LOCKED` 与剩余毫秒，解锁后任何玩家可拾取。
4. 远处拾取：点击超出 1.5 格的掉落会自动走近后提交既有拾取命令；锁定掉落只
   提示倒计时。
5. 验证：575 测试、全量 47/47 E2E、50 人 × 2 分钟 tick p95 3.4ms、0 资产
   失败、资产不变量 7/7 为 0；8584 实测自动拾取与背包脉冲。
6. 文档：ADR-041、ADR-035 §8 修订、切片报告、状态、日志与债务同步。

## S3-D2 验收（已完成）

1. 内容：新增到达目标 schema（地图、目标格、1–5 格半径）；一次性「东门巡视」
   与每日「东境巡逻」通过内容校验；旧 Release 与击杀/收集任务行为不变。
2. 权威性：完成判定只读服务端 `WorldSimulation` 位置；客户端不发送“已到达”；

   重复与并发观测都是幂等，已领取行不改写；不新增资产命令或账本。
4. 每日隔离：到达完成按 `rules.dailyReset` 的周期键写入；旧周期行不会在新一天
   被误判完成。
5. 导航：`hunt` 目的对到达任务走到目标半径内（跨图走传送门，同图选最短可达
   落脚点），不进入自动攻击；完成后以 `completed` 停止。
6. 客户端：面板/追踪器显示「到达 地图（x,y）」与“已到达/未到达”，行动按钮显示

## S3-M 验收（已完成）

1. 寻路：八方向 BFS；斜向步只有在两个正交邻格都可走时合法，禁止切角；
   同长度路径优先直线。
2. 速度：斜向按欧氏距离（约 1.414 格）计时，斜向不快于直线；服务端与客户端
   预测使用同一规则。
3. 朝向：逻辑朝向扩展为八方向（旧 0–3 不变，追加 4–7），四方向贴图在表现层
   映射；无数据库迁移。
4. 操作：WASD/方向键按住连续走、两键组合斜走；空格发送 `move.stop`，服务端
   清空路径并停止自动攻击，返回空路径 ack。
5. 验证：真实 Game Server 对角 `move.to` 到达两轴目标、`move.stop` 后位置
   稳定；真实浏览器按住 D+S 斜向移动、空格停止；全量单元/集成与 E2E 通过。
6. 文档：ADR-043、ADR-016 补充指针、切片报告、状态、日志与债务同步。

## S4-A 验收（已完成）

1. 权限：只有队长能移交与踢人；目标必须是同队成员且不能是自己；权限在
   `PartyRegistry` 判定，Room 只解析与路由，拒绝码可区分。
2. 状态：被踢者的世界会话与 presence 保留，只清空队伍名单；队长不能被踢，
   队伍至少保留队长；被踢者发出的邀请被丢弃。
3. 队伍聊天：复用 `chat.send`/`chat.message` 的可选频道，过滤/限频/禁言/去重
   与地图聊天一致；消息只投递给队伍成员，跨图由成员所在 Room 端口投递，
   不进入公开 Room State。
4. 兼容：省略 `channel` 时仍为地图聊天；无协议版本变更、无内容发布、无数据库
   迁移。
5. 客户端：频道切换与「队伍」标签；队长看到移交/踢人操作；离开或被踢后聊天
   频道自动回到附近。
6. 验证：613 个单元/集成测试、全量 50 个浏览器 E2E；真实 PostgreSQL 集成测试
   覆盖同图隐私、权限拒绝、跨图队伍聊天与名单清理。

## S4-B 验收（已完成）

1. 持久化：迁移 `0011` 新建 `friendships`；无序对唯一、发起方约束与状态检查；
   角色删除级联清理；拒绝申请删除 pending 行，删除好友删除 accepted 行。
2. 命令：`friend.request/accept/decline/remove/list` 经统一门禁；数据库操作在
   tick 之外，提交后才回复；重复申请/重复接受幂等，互相申请自动成为好友。
3. 在线状态：复用进程级 presence（ADR-036）；加入/真正离开世界时向在线好友
   推送 `friend.presence`，过图不发送离线事件；好友快照合并在线、等级与存活。
   修复了“未组队玩家离开后 presence 残留”的幽灵在线问题。
4. 好友组队：同 Room 近距离邀请规则不变；跨图或超范围只允许已接受好友，且目标
   必须在线；非好友远距邀请返回 `PARTY_TARGET_UNAVAILABLE`。
5. 客户端：好友面板（在线/离线、好友申请、已发送、邀请、删除）、附近玩家
   「加好友」与未处理申请角标；聊天日志默认显示全部频道，标题栏只筛选日志，
   输入行左侧单独选择发言频道（纯展示层，不改变服务端投递）。
6. 验证：623 个单元/集成测试、全量 51 个浏览器 E2E；真实 PostgreSQL 覆盖
   好友事务，真实 Room 覆盖跨图好友邀请与陌生人拒绝。
