## S2 验收（已完成）

1. 内容：Boss 定义、狂暴阶段、独占掉落与地图刷点全部走内容发布，历史 Release
   不受影响。
2. 服务端：阶段切换、有效属性、地图公告与掉落/经验全部服务端裁定；真实
   PostgreSQL + Room 集成测试覆盖三人击杀。
3. 客户端：真实 Chromium 能看到首领血条、首领标记与狂暴状态；首领血条不遮挡
   玩家与画面中心。
4. 容量与资产：50 人 × 2 分钟 sanity 无退化，资产不变量 7/7 为 0。
5. 文档：ADR-037、切片报告、状态、日志、债务与演进记录同步。

## S3 选择依据（下一轮）

按“价值 / 依赖 / 风险”排序：

1. **任务链扩展（10 步主线 + 日常）**：直接回答“明天回来”；依赖既有
   `character_quests` 与内容 section，不需要新架构；风险在任务数值与内容量。
2. **3 人副本实例**：多人价值最高，但需要动态 Room/实例路由 ADR、进入条件、
   复活与掉落分配；工作量明显大于一个切片。
3. **社交深化（队伍聊天/移交/踢人）**：补齐 S1 的明显缺口，工作量中等，但
   “回来”价值低。
4. **交易/排行榜**：经济与审计面大，应在内容量与留存验证后再做。

除非试玩给出相反信号，S3 优先任务链扩展；副本实例先写 ADR 再实施。
