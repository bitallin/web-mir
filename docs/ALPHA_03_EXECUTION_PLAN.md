> 版本内的切片顺序、验收与债务影响。每完成一个切片更新本文件与

  事务化 + 账本 + 审计。

## S2 验收（已完成）

1. 内容：Boss 定义、狂暴阶段、独占掉落与地图刷点全部走内容发布，历史 Release
   不受影响。
2. 服务端：阶段切换、有效属性、地图公告与掉落/经验全部服务端裁定；真实
   PostgreSQL + Room 集成测试覆盖三人击杀。
3. 客户端：真实 Chromium 能看到首领血条、首领标记与狂暴状态；首领血条不遮挡
   玩家与画面中心。
4. 容量与资产：50 人 × 2 分钟 sanity 无退化，资产不变量 7/7 为 0。
5. 文档：ADR-037、切片报告、状态、日志、债务与演进记录同步。

## S3-A 验收（已完成）

1. 内容：日常任务、重置规则与两个日常全部走内容发布；旧 Release 与一次性
   任务行为不变。
2. 服务端：重置边界是注入时钟的纯函数；接取/交付/击杀推进按周期键隔离；
   在线玩家跨过重置点会收到新快照与公告。
3. 客户端：真实 Chromium 能看到「日常」标签、重置时刻与「今日已完成」；
   追踪器正确显示 0/5 与交付后的清空。
4. 测试：11 条新增单元/集成与扩展的真实 E2E 覆盖同日重复、跨日重接与奖励唯一。
5. 容量与资产：50 人 × 2 分钟 tick p95 5.11ms、0 资产失败；不变量 7/7 为 0。
6. 文档：ADR-038、切片报告、状态、日志、债务与经验记录同步。

## S3-B 验收（已完成）

1. 服务端：一键前往/返回是服务端导航状态机；路线、目标选择、移动与到达
   全部由服务器裁定，客户端只提交意图。
2. 跨图：从主城到野外走传送门；过图后客户端重放意图，自动继续。
3. 战斗：复用既有自动攻击（射程/冷却/安全区/目标死亡），不新增伤害链路。
4. 交付：到达守卫后客户端发送既有 `quest.claim`；奖励事务、幂等与距离校验
   不变；自动交付失败回退到面板。
5. 客户端：接取并前往、回去交付、停止自动、状态横幅与进度/完成/交付提示；
   不遮挡玩家与画面中心。
6. 全局面板：任意地图打开「任务 · 全部地图」可看到所有任务的状态与发布者
   地点；从 NPC 点开时只显示该发布者。
7. 远程接取：任意地图点「前往接取」，服务端自动把角色送到发布者身边并接取，
   接取成功后自动开始狩猎；接取仍是客户端发起的既有命令，服务器校验距离与
   状态；未实现瞬移。
8. 验证：541 测试、45 个浏览器 E2E（串行全量）、资产不变量 7/7 为 0。

## S3-C 验收（已完成）

1. 内容：主线从 3 步扩展到 10 步，覆盖三张地图与全部怪物层级；奖励物品、
   前置、等级与刷点全部通过内容校验；旧 Release 的 3 步链仍可加载。
2. 发布者：废墟入口新增「废墟斥候」，后五步在野外接取/交付；NPC 角色进入

3. 可完成性：领域测试模拟“只靠该链的击杀与奖励”能从 1 级走到最后一步；
   应用集成测试用真实 PostgreSQL 完成 10 步接取→击杀→交付，奖励恰一次。
4. 客户端：任务面板按状态分组并显示数量，可操作任务优先；引导提示优先主线，
   不再被每日任务抢占；真实浏览器验证 12 条任务的分组与地点展示。
5. 容量与资产：无 tick/协议热路径变更；50 人 × 2 分钟 sanity 与资产不变量
   作为门禁；详见切片报告。
6. 文档：切片报告、状态、日志、债务与经验记录同步。

## S3-D1 验收（已完成）

1. 内容：新增收集目标 schema（闭集分支）与两条任务——一次性教学任务
   「巡路补给」（初始药水）与每日「蛛腿征募」（材料消耗）；旧 Release 的
   击杀任务不受影响。
2. 服务端：收集进度从背包汇总派生，拾取不写任务进度；交付在行锁内扣除物品、
   标记完成/已领取并发放奖励，同一事务；数量不足返回 `QUEST_ITEMS_MISSING`
   并整体回滚。
3. 导航：收集任务的「前往击杀」指向掉落该物品的怪物；背包凑够后自动停止；
   「回去交付」把已够数的活动任务视为完成。
4. 校验：目标物品必须存在且为材料/消耗品；每日不能要商店可购买的物品；
   目标物品不能同时是奖励；无来源时告警。
5. 测试：领域视图（进度/完成/领取）、真实 PostgreSQL 交付与多堆叠扣除、
   数量不足回滚、服务端背包变化刷新快照、真实浏览器接取→交付→物品减少。
6. 文档：ADR-040、切片报告、状态、日志与债务同步。

## S3-D2 选择依据（下一轮）

1. **到达类任务目标**：探索地点与半径，复用编译地图、寻路与一键导航；需要
   服务端位置事件与完成事务，工作量中等。适合作为下一片。
2. **3 人副本实例**：多人价值最高，但需要动态 Room/实例路由 ADR、进入条件、
   复活与掉落分配；工作量明显大于一个切片。
3. **队伍聊天/队长移交/踢人**（TD-CLI-17）：社交体验完整度，工作量小到中等。
4. **交易/排行榜**：经济与审计面大，应在内容量与留存验证后再做。

除非试玩给出相反信号，S3-D2 优先到达目标；副本实例先写 ADR 再实施。

## 债务影响

- S2 新增：世界首领刷新为 Room 进程内状态（TD-SRV-12），与队伍跨进程问题同类。
- S3-A 新增：每日任务历史行没有清理策略（TD-DATA-12，P3）；日常 UI 只有
  静态重置时刻，没有倒计时。
- S3-B 新增：自动战斗只用普通攻击（TD-CLI-19，P3）；导航意图是连接级状态，
  过图/断线后依赖客户端重放；Room 编排继续增长（TD-SRV-01b）。远程接取仍需
  角色自动走到发布者，未实现瞬移；跨图接取会增加一段真实旅程。
- S3-C 新增：任务面板只有状态分组，没有搜索/筛选（TD-CLI-20，P3）；废墟
  入口是开放 PvP，斥候附近没有局部安全区；地图 NPC 属于代码发布，校验前
  需重启服务（EL-040）。
- S3-D1 新增：收集任务不显示物品来源（TD-CLI-21，P3）；背包进度不落库，
  依赖 Room 授权背包快照；到达目标留作 S3-D2。
- 保持：TD-SRV-11（队伍仅内存）、TD-CLI-17（队伍聊天/分配/移交）、
  TD-CLI-13（正式美术）。
- S2 不新增数据库迁移、不改资产模型、不引入 Redis；S3-A 增加一条向前兼容
  的迁移（周期键 + 唯一索引替换），不改资产模型、不引入 Redis；S3-B 无迁移、
  无内容发布；S3-C 无迁移，发布 `2026.11.27.4`（新增 7、变更 1）；S3-D1
  无迁移，发布含 2 条收集任务的新 Release。
